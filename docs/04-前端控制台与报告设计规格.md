## 0. 文档约定与门禁自检

### 0.1 基准与范围

本轮为「文档驱动开发」专线，只产出文档与设计令牌文件，不写业务代码、不修改其他成员文档。范围严格对齐 PRD 功能需求（第 7 章）与架构文档 v2.0，不新增用户未要求功能。PRD「非目标」（实时流量拦截、在线动态脱敏、权限管控/访问审批、OCR、业务数据修改）在本控制台不提供入口。

前端只承载「配置、发起、查看、复核、导出」交互层；数据库连接、元数据遍历、抽样识别、风险分级、报告生成均由后端承担。**资产数据源配置写入后端存储数据库**，控制台提供增删改查与 Excel/YAML 批量导入界面。控制台静态资源由 Go 进程同源托管（架构文档 §13.1、§19.1），无独立 Node 服务、无跨域配置。

据项目总纲磁盘原文：报告输出 Excel / HTML / JSON 三种格式，内容可含**实例、模式、表、字段、样本、命中数、风险等级**，只放脱敏样例；流式大结果集支持服务端分页展示与导出；所有**错误信息必须中文**，不回显堆栈/连接串/密钥路径；版本统一 CalVer `2026.11.13.0`。

### 0.3 令牌引用约定（重要）

- `design-tokens.css` 的 **Primitive 段**与 `design-tokens.json` 的 `primitive` 段是唯一允许出现字面色值的位置，是 Token 源值，非组件硬编码。
- 除上表与令牌文件外，本文所有章节、组件描述、示例代码一律使用 `var(--token)` 或令牌名，不出现裸 hex；唯一例外 `#fff` / `#000`。
- 阴影与聚焦环通过 `rgb(var(--c-shadow-rgb) / alpha)` 引用，不写 `rgba(...)` 裸色值。
- ECharts `option` 不写字面色值，通过 §4.2 `useChartTheme()` 从 CSS 变量读取；图标颜色继承 `currentColor`，不单独指定色值。
- `design-tokens.json` 的 `value` 是解析后构建期字面值，可直接 `import`；`cssVar` 指向运行时 CSS 变量；`ref` 记录上游引用。CSS 是运行时真源，两者由同一张令牌表派生，禁止各自维护。

## 1. 设计方向、对标品牌与整体设计语言

### 1.1 设计寄存器、平台轴与三轴刻度

Product 寄存器（后台/仪表板/工具）：中性色占 80% 以上、仅一个强调色、语义色只用于状态；Sans-Serif 为主，Dashboard 禁 Serif；功能性动效为主、`--motion-fast` 150ms 收敛、无装饰性持续动画；以真实数据、状态徽章、表格、图表替代照片。平台轴 **web**（桌面宽屏主场景，平板次之，手机仅关键状态可查看）。

| 参数 | 取值 | 依据 |
|---|---|---|
| `DESIGN_VARIANCE` | **3** | 企业后台要求可预测、对称、操作路径短；严格 12 列栅格与等距 padding，禁非对称 Hero 与艺术化布局 |
| `MOTION_INTENSITY` | **2** | 合规工具动效只承担状态确认；禁脉冲/浮动/视差；`prefers-reduced-motion` 下归零 |
| `VISUAL_DENSITY` | **7** | 字段台账高信息密度；1px 分隔线、紧凑行高、等宽数字；仅总览页保留少量 KPI 卡片 |

密度档通过 `data-density` 覆盖（§5.6），默认 `default`（行高 44px），结果台账允许 `compact`（36px）。`<768px` 回退单列。

### 1.2 竞品调研结论与对标

调研四组（阿里云 DSC、奇安信数据运营态势感知、DataHub/OpenMetadata/Atlas、数据密集型仪表板色彩实践），行业共识：**中性结构 + 语义色只用于状态 + 表格为主 + 分级图表下钻**。本期不采用全屏态势大屏，而采用「任务链侧栏 + 真实数据首屏 + 可下钻台账」的桌面工作台形态。

| 对标 | 借鉴点 | 理由 |
|---|---|---|
| **Linear**（主对标） | 克制中性色层次、单一强调色、紧凑列表、键盘优先 | Product 寄存器交互与信息层次标杆 |
| **Stripe Dashboard** | 数据密集表格、财务级精确数字、明细下钻 | 字段台账与报告是可审计产物，需严谨留痕 |
| **Vercel Dashboard** | 状态徽章、任务进度、运行中实时反馈 | 对应扫描任务状态机与进度/失败表回显 |
| **Grafana** | 图表语义、状态色纪律、图例与阈值标注 | 报告中心 ECharts 遵循「颜色即信息」 |
| **阿里云 DSC** | 分级环形图、识别率柱状、命中模型 TOP 榜 | 与「分类分级 + 台账」产品语义一致 |

未选方向：营销型落地页、全屏 3D 态势大屏、消费级圆润卡片。主色取**深藏青**，交互强调色取**沉稳蓝**而非默认靛蓝（避免「默认靛蓝一眼 AI」反模式）。企业规范「勿用紫/粉渐变」「勿用 emoji 做功能图标，用 Lucide」直接落为 P0 红线；图标库取值与架构文档 §19.2 一致。

### 1.3 整体设计语言、字体与配色

**禁止千篇一律 Hero**：首屏（`/`）在 `--topbar-h` 之下直接进入内容，无任何营销区。

| 区域 | 内容（真实产品数据） | 组件 |
|---|---|---|
| 状态摘要行 | 4 个 KPI：数据源总数 `{instanceTotal}`、连接异常 `{abnormalCount}`、运行中任务 `{runningTasks}`、高风险字段 `{highRiskFields}`；数字 `--font-mono` + `tabular-nums` | `*OverviewKpiStrip`，4 个 `--card-*` 卡片，每卡一 24px 图标 |
| 左主区（8 列） | **数据源列表**：实例标识、主机/端口（§4.6 脱敏）、只读账号、连接状态、最近扫描时间、行操作 | `*DataSourceStatusTable` |
| 右上（4 列） | **扫描进度**：任务状态徽章 + 分段进度条 + 已用时 + 低峰窗口提示 | `*ScanProgressCard` |
| 右下（4 列） | **风险分布**：环形图（高/中/低/待复核）+ 图例 | `*RiskDistributionCard`（ECharts `pie`） |
| 通栏 | **字段台账**最近 8 条：实例/模式/表/字段、敏感类型、命中率、风险等级、复核状态 | `*RecentFindingsTable` |

卡片为 `--card-elev`(1px 边框环、无阴影)、`--card-radius`(12px)、`--card-padding`(20px)，不用彩色左边框/发光边框/装饰性毛玻璃；标题 `--text-sm`+`--weight-emphasize`+`--fg`，不用 ALL CAPS 追踪标签、不用编号 section 标记。

字体：展示 **Archivo**、正文 **Inter**、中文回退 **Noto Sans SC**、数字/掩码/SQL/字段名 **JetBrains Mono**；字重 510/590 可变取值，Noto Sans SC 按 `staticFallback` 回退 500/600。配色：中性 ~82%（浅冷灰 `--bg`、白 `--surface`、灰阶分隔，不用奶油/米色暖中性）；强调 ~8%（`--accent` 单一沉稳蓝，每屏 ≤2 处）；语义 ~9%（`--success`/`--warn`/`--danger`/`--info` 及风险四级令牌）；效果 <1%（聚焦环/遮罩/阴影，由 `--c-*-rgb` 派生）。氛围：**刻度感、可归档、克制、可追溯、冷静**。

### 2.2 应用壳层（App Shell，全站共用）

- 左侧 Sidebar（宽 `--sidebar-w`，可折叠至 `--sidebar-w-collapsed`）：背景 `--surface-brand`，文字 `--fg-on-brand`；按任务链分 5 组（认知负荷 ≤5）：**概览**（P01）、**资产**（P02/P03/P04）、**识别**（P05/P06/P11）、**结果**（P07/P08）、**交付**（P09/P10/P12）。单项高度 ≥ `--touch-target-min`；激活态用 `--surface-selected` 背景 + `--accent` 图标与文字 + `--weight-emphasize`，**不用侧边条纹或彩色左边框**。
- 顶部 Topbar（高 `--topbar-h`）：面包屑、全局搜索（`Cmd/Ctrl + K`）、当前规则版本徽章、通知、当前管理员账号与登出。
- 内容区：最大宽 `--container-max`，栅格 12 / 8 / 4 列，沟槽 `--gutter-*`。
- 全局：Toast 容器（`--z-toast`）、确认对话框（`--z-modal`）、骨架屏、错误边界、认证拦截层。
- **认证边界（§13.1、U-08）**：本期为**单管理员 + 会话**，除 `POST /api/v1/auth/login` 外所有端点需 `Authorization: Bearer <token>`；token 哈希存服务端，前端只持会话令牌；错误码 `1002`（中文「登录状态已失效，请重新登录」）触发跳转 `/login`；会话过期界面仅提供重新登录。**不做 SSO / LDAP / 企业身份源集成、不做多角色与权限矩阵界面**，P13 不出现身份源选择、组织切换、角色分配等控件。

## 3. 资产数据源增删改查与 Excel / YAML 批量导入完整交互流程

> 硬性门禁：**连接测试通过才保存**，由架构文档 §13.2 `POST /api/v1/datasources`（新建）与 `PATCH /api/v1/datasources/{id}`（编辑，含凭据变更时）在后端原子保证，失败返回 `2001` 中文错误且整条不落库（验收项 A7）。批量导入同一门禁按逐条粒度执行：逐条连接测试＋逐条独立事务，通过的行入库、失败行不入库并逐行中文回显，允许部分成功（partial）、重复导入幂等去重（03 规格契约第 5 章）。

### 3.2 CRUD 完整流程

- **列表（Read）**：`GET /api/v1/datasources?page=&limit=&dialect=&keyword=&sort=`。列：实例标识、方言、脱敏后主机:端口、服务名、只读账号、连接状态、最近扫描时间、行操作。默认排序：连接异常优先，其次最近扫描时间倒序。空状态中文引导「配置第一个数据源」，直达 P03 与 P04。
- **新建（Create）**：`/datasources/new` → 3 步表单逐字段失焦校验（中文错误紧贴字段）→ 提交前全量校验 → 「测试连接并保存」调用 `POST /api/v1/datasources` → 后端先执行只读连接测试，通过才落库返回 `{id, lastTestOk}`；失败返回 `2001` 中文 `message`，整条不落库 → 成功中文 Toast 并跳转 P02 高亮新行，失败保留表单与草稿（剔除 `password`）。
- **编辑（Update）**：`GET /api/v1/datasources/{id}` 回填；凭据字段显示「已配置，留空表示不修改」（占位串）；保存调用 `PATCH /api/v1/datasources/{id}`，**含凭据变更时后端强制重新连接测试**；另提供「只读重测」按钮调用 `POST /api/v1/datasources/{id}/test`（只读探针，不改动配置）。
- **删除（Delete）**：行操作「删除」→ 中文二次确认 → `DELETE /api/v1/datasources/{id}`（软删除）。存在运行中任务时后端拒绝并给中文提示，前端原样回显 `message`，提供跳转 P06。

### 3.3 连接测试门禁（硬性规则）

状态机：`idle → testing → success | fail`，其中 `testing → success/fail` 由 `POST /api/v1/datasources` 的原子响应驱动。

| 状态 | 视觉 | 保存 |
|---|---|---|
| `idle` | 中文「尚未验证连接」+ `--state-idle-*` | 必填校验未过时按钮禁用 |
| `testing` | `LoaderCircle` + 中文「正在校验只读连接…」+ 耗时 | 按钮 `loading` 态禁用，防重复提交 |
| `success` | `CircleCheck` + 中文「连接成功，只读账号校验通过，配置已保存」+ `--state-success-*` | 已完成 |
| `fail` | `CircleX` + `2001` 中文 `message` 与修正建议 + 「重试」+ `--state-failed-*` | 配置未落库 |

失败分类（由后端中文 `message` 给出，前端不自行枚举技术细节）：网络不可达 / 认证失败 / 账号非只读 / 连接超时 / 驱动或版本不兼容 / 系统模式排除校验失败。每类给一条可操作中文建议，例如「账号非只读：请改用只读账号后重试」。

设计约束：编辑态 `test` 为**只读探针，不改动配置**，其 `success` 仅表示当前连通性，不能替代 `PATCH` 保存时的重新测试；批量导入同样执行本门禁（§3.4 阶段 2）；测试结果带时间戳，连接字段变更后 `idle` 复位并给中文原因；前端**不得**自行拼接连接串、不得缓存凭据、不得在错误信息中回显密码或完整主机。**待验证**：新建态是否需要「不落库独立探针端点」支持两步 UI（§13 U2）。

### 3.4 Excel / YAML 批量导入四阶段流程

**设计前提**：文件解析、逐行校验、逐条连接测试、逐条独立事务提交全部由后端在单次 `POST /api/v1/datasources/import` 内完成；前端不引入未锁定解析库，不直连存储库。响应 `{total, succeeded, failed, errors:[{row, message}]}`，`message` 一律中文。**逐条门禁 + 部分成功：逐条连接测试＋逐条独立事务，通过的行入库、失败行不入库并逐行中文回显，允许 partial，重复导入幂等去重**（03 规格契约第 5 章）。冲突策略（跳过/覆盖）本期不提供 UI，列入 §13 未决项。

| 阶段 | 用户动作 | 前端 | 后端接口 | 结果 |
|---|---|---|---|---|
| 1 准备 | 下载模板；选择 `.xlsx`/`.xls`/`.yaml`/`.yml` | 模板下载；前端预检扩展名、大小（≤10MB）、行数（≤5000）、文件数量；说明列头与字段映射 | `GET /api/v1/datasources/import/template?format=excel\|yaml` | 得到规范模板；不上传、不暂存文件 |
| 2 提交与逐条处理 | 点「导入 {n} 个数据源」；中文二次确认 | 分阶段进度：上传→解析→逐行校验→逐条连接测试→逐条事务提交；`loading` 禁用防重复 | `POST /api/v1/datasources/import`（`multipart/form-data`） | 后端逐条独立事务完成；返回 `total/succeeded/failed/errors` |
| 3 结果回显 | 查看成功/失败清单 | 逐行结果表：行号、实例标识、状态徽章、中文 `message`；成功「已导入 {succeeded} 个」、失败「{failed} 行未通过，未入库」 | 同上响应 | 每行 `row`+中文 `message` 近行回显；不显示「导入失败」笼统文案 |
| 4 失败处置 | 下载错误清单；仅修正失败行后重新导入 | 前端本地生成结构化错误清单（行号+中文原因），不新增端点；「重新选择文件」回阶段 1 | 无新增端点 | 仅重传失败行；按 `name` 幂等去重 |

补充：阶段 2 逐条连接测试并发由后端控制，前端不发起 N 次连接（低侵入）；全流程中文错误与提示，刷新页面不保留未提交文件（文件不落地前端）；状态机 `idle → selected → uploading → processing → done | failed`，`failed` 保留已选文件与错误清单可「重新选择」而非强制刷新。

### 3.5 校验分层与失败回显 / 冲突幂等

| 层级 | 校验项 | 回显位置 |
|---|---|---|
| 文件级（前端） | 扩展名、大小、行数、文件数量 | 上传区顶部中文 Alert + 重新选择 |
| 行级（后端） | 必填项、主机格式、端口范围、`name` 格式、模式清单合法性、排除正则语法、重复行 | 阶段 3 逐行表：`row`+中文 `message`，失败行底色 `--danger-bg` 低饱和 |
| 业务级（后端） | 与库中现有 `name` 冲突、只读账号缺失、凭据不可解析 | 阶段 3 冲突行中文 `message` |
| 连接级（后端） | 连通性、只读账号校验、方言版本、系统模式排除 | 阶段 3 该行中文失败分类；该行不入库，其余通过行照常（部分成功） |

### 4.2 图表主题桥接（禁止硬编码颜色落地做法）

ECharts 需具体色值，但 `option` 不写裸 hex。约定 `useChartTheme()`：

```
const readVar = (name) =>
  getComputedStyle(document.documentElement).getPropertyValue(name).trim();
const chartTheme = {
  risk: { high: readVar('--risk-high-fill'), medium: readVar('--risk-medium-fill'),
          low: readVar('--risk-low-fill'), pending: readVar('--risk-pending-fill') },
  series: [1,2,3,4,5,6].map((i) => readVar(`--chart-${i}`)),
  axis: readVar('--chart-axis'), grid: readVar('--chart-grid'),
  label: readVar('--chart-label'), fontFamily: readVar('--font-body'),
  textColor: readVar('--muted'),
};
```

要点：组件内 `option` 一律引用 `chartTheme`；读取在客户端组件挂载后执行，避免 SSR 阶段 `document` 不可用；`design-tokens.json` 的 `cssVar` 用于构建期校验令牌名拼写；未来深色主题只需覆盖 `:root[data-theme="dark"]`，图表无需改动（本期不实现）。

### 5.7 令牌使用红线

1. 组件样式禁裸 hex（例外 `#fff`/`#000`）；阴影/聚焦环走 `rgb(var(--c-*-rgb) / a)`；图标继承 `currentColor`。
2. 禁按色相命名语义令牌（如 `--blue`/`--red`），一律按用途命名。
3. 禁在组件写死间距、圆角、时长数值，全部引用令牌。
4. 禁「1px 实线边框 + blur≥16px 阴影」同元素叠加。
5. 新增或变更令牌须同步 `design-tokens.css`、`design-tokens.json` 与本章，并在变更记录追加一行。

### 8.2 对比度核验（WCAG 2.1 AA，正文 ≥4.5:1）

| 前景 / 背景 | 用途 | 对比度（约） | 结论 |
|---|---|---|---|
| `--fg`/`--fg-2`/`--muted` on `--surface` | 主/次/副文本 | 15.8 / 10.9 / 7.5:1 | 通过 |
| `--meta` on `--surface` | 元数据/辅助文字 | 4.6:1 | 通过（仅 ≥12px 辅助文字） |
| `--accent-on` on `--accent` | 主按钮文字 | 6.7:1 | 通过 |
| `--fg-on-brand` on `--surface-brand` | 侧栏文字 | 11.0:1 | 通过 |
| `--risk-{high,medium,low,pending}-fg` on 对应 `--bg` | 风险四徽章 | 6.3 / 5.9 / 5.4 / 6.6:1 | 通过 |
| `--border` on `--surface` | 输入框边框（非文本） | 1.5:1 | 非文本对比，配合 `--focus-ring` 与中文 label 满足可辨识 |

`--meta` 仅用于 12px 以上辅助文字；所有状态除颜色外均有图标 + 中文文字（§4.4/§4.5）；图表图例带文字标签；打印/灰度场景可读。

### 8.3 键盘操作与焦点态

- 全局：`Tab`/`Shift+Tab` 顺序与视觉一致；`Cmd/Ctrl + K` 全局搜索；`Esc` 关抽屉/对话框/菜单；表格行 `Enter` 开详情、`Space` 切换选中。
- 焦点：所有可交互元素 `:focus-visible` 显示 `--focus-ring`；抽屉/Modal 打开焦点移入并锁定，关闭回触发元素；Toast 不抢焦点，用 `aria-live` 播报。
- 图标按钮必须**中文** `aria-label`；纯装饰图标 `aria-hidden="true"`；折叠态导航提供中文 Tooltip 与 `aria-label`；表格排序用 `aria-sort`；进度条用 `role="progressbar"`+`aria-valuenow`；状态徽章用可见中文文字而非仅颜色。
- 危险操作（删除、批量导入、重试任务）中文二次确认，焦点默认落「取消」。
- `1002` 会话过期焦点移至登录表单首个输入框并给中文提示。

### 8.4 表单错误提示（中文）

- 每个输入框有可见中文 `<label>`，不以 placeholder 代替 label。
- 错误提示紧贴字段下方，**全中文**，含：具体字段、当前问题、修正建议（§3.5 四要素）；字段用 `aria-invalid="true"`+`aria-describedby` 关联中文错误文案。
- 失焦校验 + 提交前全量校验；提交有错时焦点自动移首个错误字段并滚动可见。
- 错误汇总仅长表单（P03/P13）顶部额外提供，每条可点跳转；不能只在顶部显示。
- 后端 `message` 一律中文（§2.4），前端**不得**改写为英文、不得拼接堆栈/连接串/密钥路径/完整主机。
- 批量导入逐行错误等同表单错误：行内中文 `message` + 可下载错误清单 + 中文错误行数汇总。

### 8.5 触摸目标与动效降级

- 所有可点击区域 ≥ `--touch-target-min`（44×44px）；视觉小于该值用 padding 扩展点击区；相邻按钮间距 ≥ `--space-2`。
- 不依赖 hover 作唯一交互（表格行操作在触屏常驻或长按唤出）。
- `prefers-reduced-motion: reduce`：CSS 归零 `--motion-*` 并禁动画/过渡；`LoaderCircle` 旋转停止，进度以中文文本百分比表达。
- 支持浏览器 200% 缩放不丢内容与操作；不使用 `user-scalable=no`。

## 9. 主题：浅色为主的选择理由

**结论：本期仅实现浅色主题（`data-theme="light"`），深色主题作为 C-extension 预留但不实现，也不在 P12 提供切换开关。**

1. **环境约束**：用户已确认当前为浅色主题环境。
2. **使用场景**：DBA/安全合规/审计人员长时间阅读字段台账与报告，浅底深字疲劳度更低；报告需投屏评审、打印归档、导出 HTML 留痕，白底是合规文档通用载体。
3. **语义色可辨性**：风险语义（红/琥珀/绿）与状态色在浅色中性底更易达标（§8.2 已逐项核验）；深色底需重设整套语义色阶，本期不做半成品。
4. **克制原则**：深色不在本期确认范围，提供半成品切换开关反而增维护与验收成本。
5. **未来可扩展**：所有颜色已通过语义令牌引用，图表色由 `useChartTheme()` 读取（§4.2）。后续需深色只需新增 `:root[data-theme="dark"]` 的 Primitive 覆盖并重跑对比度核验，业务组件与图表 `option` 无需改动。

与 P0 一致：不使用任何渐变主视觉、发光边框、装饰性毛玻璃；品牌深藏青只作侧栏结构表面，唯一强调色为纯色沉稳蓝。

## 10. Do's and Don'ts

**应做**
1. 首屏直接展示真实产品内容：数据源列表、扫描进度、风险分布、字段台账。
2. 所有颜色、间距、圆角、字号、时长通过令牌引用；ECharts 色值由 CSS 变量读取；图标继承 `currentColor`。
3. 图标只用 `lucide-react@1.72.0` 具名导入，尺寸仅 16/20/24px，锁 lock 文件禁浮动。
4. 表格数字用 `--font-mono` + `tabular-nums`；风险徽章色块+图标+中文文字三重编码。
5. 连接测试通过才保存（后端原子保证）；失败以中文回显到具体字段/行并给可操作建议。
6. 报告只放脱敏样例；IPv4 前两段 `*`、`127.0.0.1` 与 `localhost` 保留、其余 `*`；SQL 字面量、日志、报告三处脱敏。
7. 表单有可见中文 label、近字段中文错误、提交前全量校验；列表有中文空状态与重试。
8. 卡片用 1px 边框环或 ≤8px blur 阴影，二者不同时用；圆角上限 16px。
9. 每个交互组件覆盖 9 态；所有页面覆盖响应式断点与 `prefers-reduced-motion`。
10. 接口路径只引用 §13.2；统一响应 `{code,data,message}`、`page/limit/hasMore`、中文 `message`。

**禁止**
1. 禁 emoji 作功能图标；禁混用其它图标库、图标字体、自绘 SVG、0.x legacy 别名、全量 `import * as icons`。
2. 禁 Indigo 到 Pink 任意渐变、渐变文字、发光边框、装饰性毛玻璃、三位一体 AI 模板套路。
3. 禁「大标题+副标题+居中 CTA+抽象 3D 图形」Hero；禁英文欢迎语、拉丁占位文本、注册诱导语等空洞文案。
4. 禁硬编码颜色值、非 4 倍数间距、≥24px 卡片圆角、弹跳/overshoot 缓动、超 300ms 动效。
5. 禁彩色卡片左边框、侧边条纹、每节小型大写追踪标签、编号 section 标记、相同卡片无限重复网格、虚构指标。
6. 禁在前端任何位置展示、存储、拼接完整明文敏感值；禁日志打印凭据与完整证件号、完整主机。
7. 禁仅靠颜色传达状态；禁纯图标导航无中文文字标签；禁移除 focus ring。
8. 禁奶油/米色/纸色暖中性背景作默认底色；禁默认靛蓝作强调色。
9. 禁「1px 实线边框 + blur≥16px 阴影」同元素叠加；禁动画 `width/height`；禁同时超 3 个元素动画。
10. 禁引入锁定清单之外前端依赖；禁另造一套接口命名；禁把 SSO/LDAP/多角色权限界面画进本期。
11. 禁任何非中文错误信息、API `message` 回显、日志文案改写。
