## 1. 设计目标与约束

### 1.1 目标

离线、只读、可私有化部署的数据库敏感数据发现工具，对多种关系型数据源做字段级敏感资产盘点：

```
数据源配置（连接测试通过后保存） → 元数据采集 → 每列抽样 → 自研识别引擎 → 聚合分级 → 落库 → 控制台 / 报告
```

四条硬目标：

1. **多源统一**：一套数据源抽象覆盖 Oracle、达梦、MySQL、PostgreSQL、openGauss；首批实现 Oracle 与达梦。
2. **低侵入**：只读连接、每列默认抽样 20 行、主键范围分页、分批限流、低峰执行、大表降级。
3. **可追溯**：规则版本快照、任务参数、样本量、复核结论、审计日志全程留痕。
4. **凭据不出明文**：数据源密码与 IP 等敏感配置以 `ENC(base64)` 加密存储，密钥独立托管。

### 1.2 约束（来自总纲，不可协商）

| 编号 | 约束 | 落地方式 |
|---|---|---|
| C1 | 四层 DDD + 整洁架构，依赖只向内 | 见第 4 章；`domain` 不 import 任何外层包 |
| C2 | TDD 设计思想 | 接口先定、测试先行；校验器/掩码/加解密均须有正负用例 |
| C3 | Go 1.25.10+ | `go.mod` 声明 `go 1.25.10` |
| C4 | 统一入口 `dbdlp.toml`，优先级 命令行 > toml > 默认值 | 见第 8 章 |
| C5 | 日志五级（默认 INFO），中文 UTF-8，按日轮转保留 32 天 | 见第 9 章 |
| C6 | SQLite WAL 模式，数据 `data/`；可选 PostgreSQL | 见第 10 章 |
| C7 | 错误信息一律中文；日志、报告、SQL 字面量均脱敏 | 见第 9/14 章 |
| C8 | 大结果集流式读取，支持分页展示与导出 | 见第 12 章 |
| C9 | 仅只读连接、连接池；禁任何写操作与 DDL 施加于被监控库 | 见第 5 章 |
| C10 | 资产数据源配置落后端存储库，增删改查 + Excel/YAML 批量导入 | 见第 10/13 章 |

### 1.3 本期不做（out-of-scope）

- 不接入实时流量拦截、网关代理、在线动态脱敏改写。
- 不实现 BLOB/图片 OCR、dexp 备份集扫描、视图与存储过程源码扫描（列扩展点）。
- 不实现 NER 语义识别（人名/地址/公司名）、不接入 OpenDLP 或任何外部模型。
- 不实现多租户、RBAC 细粒度审批流；控制台本期只提供单管理员 + 会话认证。
- 不实现自动血缘/主备全链路遍历、跨实例分布式调度。
- 不引入 Redis、消息队列、对象存储等外部中间件。
- 不做自适应采样（总纲标注「后续增强」）。

## 2. 技术选型对比矩阵

评分维度：学习成本、生态成熟度、部署成本、团队熟悉度、与总纲契合度（权重：契合度 ×2，余 ×1）。

### 2.1 维度一：多数据源驱动抽象

| 方案 | 描述 | 契合度 | 总分 | 结论 |
|---|---|---|---|---|
| A. 每种库各写一套采集 | 按类型分目录各自读字典/采样 | 1 | 14 | 否决：违反统一数据源抽象 |
| B. `database/sql` + 统一 `Driver` 端口 + 方言适配器，**首批 Oracle/达梦** | domain 定义只读驱动接口，infrastructure 按方言实现 | 5 | 25 | **锁定** |
| C. 引入 ORM（GORM 等） | 用 ORM 屏蔽差异 | 2 | 18 | 否决：元数据/主键分页/只读强制/流式均需原生 SQL |

### 2.2 维度二：识别引擎自研与复用

| 方案 | 描述 | 契合度 | 总分 | 结论 |
|---|---|---|---|---|
| A. 内嵌 `bytedance/godlp` 内核 | v1.0 路线：调用 `Detect/DetectMap/DetectJSON` | 1 | 16 | 否决：总纲要求自研四层 |
| B. **自研分层引擎**：字节扫描器 + 正则 + 校验 + 自定义 YAML，godlp 仅参考 | 见第 6 章 | 5 | 24 | **锁定** |
| C. 纯正则 + 校验器 | 每值直接跑全量正则 | 2 | 20 | 否决：总纲要求字节扫描前置过滤 |

### 2.3 维度三：存储与部署形态

| 方案 | 描述 | 契合度 | 总分 | 结论 |
|---|---|---|---|---|
| A. 纯文件（JSON/CSV）落盘 | 任务与台账写文件 | 1 | 15 | 否决：无法支撑控制台增删改查/分页/复核回流 |
| B. **SQLite WAL 单文件 + 可选 PostgreSQL，Go 单二进制 + 内嵌控制台静态资源** | `data/dbdlp.db`，`modernc.org/sqlite` 纯 Go 无 CGO | 5 | 25 | **锁定** |
| C. 强制 PostgreSQL / MySQL 服务端 | 起步即部署独立库 | 2 | 14 | 否决：抬高内网/信创部署门槛 |

B 方案理由：SQLite WAL 支持读写并发，纯 Go 可 `CGO_ENABLED=0` 交叉编译单二进制；存储收敛到 `Store` 端口，切 PG 只换适配器。

## 4. 四层 DDD + 整洁架构

### 4.1 分层职责

| 层 | 包 | 职责 | 禁止 |
|---|---|---|---|
| 领域层 | `internal/domain` | 实体、值对象、领域服务（风险分级/置信度/掩码/存储形态）、**端口**（`Driver`/`Engine`/`Store`/`Reporter`/`Cipher`/`Logger`） | import 任何外层包；禁 `database/sql`、`net/http`、驱动、TOML、excelize |
| 应用层 | `internal/application` | 用例编排（建任务/扫描/复核/导入/报告）、事务、DTO、断点续扫状态机 | import `net/http`；直操数据库；只依赖 domain 端口 |
| 基础设施层 | `internal/infrastructure` | 实现 domain 端口：五方言适配器、自研引擎、SQLite/PG 仓储、ENC 加解密与密钥、TOML、日志轮转、报告 | 定义业务规则；被 domain 反向 import |
| 接口适配层 | `internal/interfaces` | CLI（`scan`/`report`/`retry`/`serve`/`datasource`）、HTTP 控制台 API | 写业务逻辑、直查库 |

### 4.2 依赖方向图（依赖只向内）

```text
  interfaces（CLI / HTTP Handler+Middleware）
        │ 调用用例
        ▼
  application（用例编排 / 事务 / DTO / 断点状态机）
        │ 调用端口接口
        ▼
  domain（实体 / 值对象 / 领域服务 / 端口接口）◄── 实现（依赖倒置）
        ▲
  infrastructure（方言驱动 / 引擎 / 仓储 / 加解密 / 日志 / 报告）
  规则：interfaces → application → domain ← infrastructure
  禁止：domain → 外层；application → interfaces；infrastructure → application
```

## 5. 多数据源驱动抽象

### 5.1 驱动端口接口（`domain/port`，中文注释）

```go
// Dialect 被监控数据库类型。首批 Oracle 与 Dameng，余为可扩展枚举。
type Dialect string
const (
    DialectOracle    Dialect = "oracle"
    DialectDameng    Dialect = "dameng"
    DialectMySQL     Dialect = "mysql"
    DialectPostgres  Dialect = "postgres"
    DialectOpenGauss Dialect = "opengauss"
)

// ReadOnlyConn 只读连接句柄，封装 *sql.DB 与连接池，禁暴露写方法。
type ReadOnlyConn interface {
    Ping(ctx context.Context) error
    Query(ctx context.Context, q string, args ...any) (Rows, error) // 禁 Exec / DDL
    Close() error
}

// Rows 流式结果集抽象，逐行 Scan，避免一次性加载大结果集。
type Rows interface {
    Next() bool; Scan(dest ...any) error
    Columns() ([]string, error); Err() error; Close() error
}

// Driver 统一数据源驱动端口；上层采集/采样/聚合只依赖本接口。
type Driver interface {
    Dialect() Dialect
    Connect(ctx context.Context, src DataSourceConfig) (ReadOnlyConn, error)
    ListSchemas(ctx context.Context, conn ReadOnlyConn) ([]Schema, error)
    ListColumns(ctx context.Context, conn ReadOnlyConn, schema string) ([]ColumnMeta, error)
    TableStats(ctx context.Context, conn ReadOnlyConn, schema, table string) (TableStats, error)
    SampleRows(ctx context.Context, conn ReadOnlyConn, q SampleQuery) (RowBatch, error)
    Placeholder(i int) string // Oracle :1 / PG $1 / MySQL·DM ?
    QuoteIdentifier(name string) string
}
```

### 5.2 只读连接与连接池

- 每个被监控实例一个 `*sql.DB` **目标库只读连接池**；池参数以 `data_source` 表**每实例字段**为准：`conn_max_open`（默认 2）、`conn_max_idle`（默认 1）、`conn_timeout_ms`（10000）、`query_timeout_ms`（30000，见 10.3 DDL）；默认值由 `dbdlp.toml` 提供、可按实例字段覆盖。
- 与后端本地存储库 **SQLite 单写者池**严格区分：后者固定 `storage.max_open_conns=1`（8.2/8.3/10.4）。两套独立连接池、两组独立参数，禁混用（DIFF-01 裁定）。
- **只读守卫**：`readonly.go` 在 `Query` 入口白名单校验，仅允许 `SELECT`/`WITH` 开头的单条语句；出现 `INSERT`/`UPDATE`/`DELETE`/`MERGE`/`DROP`/`ALTER`/`CREATE`/`TRUNCATE`/`CALL`/`EXEC`、分号多语句、注释符绕过时直接拒绝并记 WARN。数据库账号本身须只读，代码守卫是第二道防线。
- 连接测试（`TestConnection`）：`Connect`→`Ping`→`SELECT 1` 等价方言探针，全成功才保存（总纲「当且仅当连接测试验证成功时保存」）。

### 5.3 方言差异表（设计基线，落地前按目标库字典复核）

## 7. 加密与密钥

### 7.1 `ENC(base64)` 载荷布局

被监控数据源密码、IP 等敏感配置（总纲第 204 行）以 `ENC(<base64>)` 存储；加载时自动解密，保存时自动加密。

```text
存储形态：  ENC(Base64(载荷))
载荷布局（顺序固定）：┌──────┬─────────┬──────────┬────────┐
                     │标签1B│nonce12B│密文变长 │tag16B │
                     └──────┴─────────┴──────────┴────────┘
  0x00 → AES-256-GCM（主选；密钥用完整 32 字节）
  0x01 → SM4-GCM（国密候选，用前 16 字节）；本期落 SM4-GCM，SM4-GCM-SIV 为待切换候选
```

- nonce 每次 `crypto/rand` 独立生成 12 字节，同密钥严禁复用。
- 认证 tag 固定 16 字节，由 AEAD `Seal` 追加密文尾部；解密校验失败即报错，绝不返回部分明文。
- 载荷最短 = 1 + 12 + 0 + 16 = 29 字节；不足直接判非法密文。
- **避免循环加密**：写入前判断是否已 `ENC()` 包裹；解密自动识别 `ENC()`，非 `ENC()` 按明文返回。

### 7.2 算法标签路由

```
加密：按 crypto.default_algorithm（默认 aes256gcm）选标签 → 已含 ENC() 则跳过 → 生成 nonce → Seal → Base64 → 包 ENC()
解密：识别 ENC() → Base64 解码 → 读第 0 字节 → 按标签选实现
      → 取密钥长度（0x00 全 32B / 0x01 前 16B）→ Open → 校验 tag
      未识别标签 → 直接报错终止，不猜测、不回退；SM4-GCM-SIV 启用须保证 0x01 旧密文仍可解
```

### 7.3 密钥管理

| 项 | 规定 |
|---|---|
| 生成 | 首次运行自动生成 **32 字节**随机密钥（`crypto/rand`）写入密钥文件；禁手工编辑 |
| 存放 | `项目根目录/.dbdlp/key`（二进制），Unix `0600`；Windows 等效当前用户独占 ACL |
| 使用 | AES-256-GCM 用完整 32 字节；SM4-GCM 用前 16 字节 |
| 查找顺序 | `--config-dir` ＞ 项目根 `./.dbdlp` ＞ `~/.dbdlp`；亦可由 `dbdlp.toml` 的 `config_dir` 键指定 |
| **失败处理** | **密钥获取失败（损坏/长度错/环境变量无效/权限不足/不存在）直接报错终止进程**，绝不回退默认密钥、全零密钥、临时密钥、或降级明文 |
| 轮换 | 本期不自动轮换；轮换需停机，旧密钥解密全量 `ENC()` 后以新密钥重加密并原子替换 |

### 7.4 保存自动加密

- 数据源新增/修改时，`password`、`host`（IP）、连接串敏感片段在**写入存储库前**由 `Cipher` 加密为 `ENC(...)`。
- 读取时自动解密仅用于建连；明文凭据仅内存短时存在，不落日志、不进报告、不返前端（API 密码恒返回占位串）。

### 7.5 数据源配置（统一持久化到后端存储库）

- 被监控数据源配置**不再用文件系统文件**，统一持久化到 `data_source` 表（增删改查 + Excel/YAML 批量导入）；命令行/TUI 经控制台 API（第 13 章）或 CLI（`datasource add`/`datasource import`）写入，**不维护独立本地数据源配置文件**。字段：`name`/`dialect`/`host`/`port`/`service_name`/`username`/`password`/`dsn`/连接池参数/`include_schemas`/`exclude_tables`/`exclude_columns`/`enabled`/`remark`；敏感字段（`password`/`host`/可选 `dsn`）写入前一律 `ENC(...)`。
- **查找顺序**（密钥 `.dbdlp/key`、`dbdlp.toml`、`configs/rules.yaml` 基准目录）：`--config-dir` ＞ 项目根 `./.dbdlp` ＞ `~/.dbdlp`；命中即止不合并。`dbdlp.toml` 的 `config_dir` 键等效 `--config-dir`。
- **写入入口受限**：仅 TUI 向导 / CLI / 控制台 API 可创建更新；复用同一套 application 用例与保存门禁，绝不提供绕门禁直改 `data_source` 表路径。
- **当且仅当连接测试验证成功时才保存**：失败抛中文错误，不写库、不留半条记录。
- 批量导入（Excel/YAML）**逐条门禁 + 部分成功**：逐条连接测试、每行独立事务单独提交；通过行入库、失败行不入库并以 `{row, message}` 逐行中文回显，最终 `{total, succeeded, failed, errors}` 汇总；**不做整批回滚**。重复导入按唯一键幂等去重（DIFF-01 裁定）。

### 7.6 路径命名定案（U-06 已关闭）

经用户裁定：配置目录与密钥文件统一为 `.dbdlp/key`（对齐 `AGENTS.md`，保留 `0600` 与 `--config-dir` ＞ 项目根 `./.dbdlp` ＞ `~/.dbdlp`）；数据源配置文件已移除，仅持久化到 `data_source` 表。

|---|---|
| 级别 | `TRACE`/`DEBUG`/`INFO`/`WARN`/`ERROR` 五级（顺序 TRACE>DEBUG>INFO>WARN>ERROR），**默认 INFO**；`FATAL/PANIC` 内部保留不开放。TRACE 微步骤、DEBUG 模块细节、INFO 关键状态、WARN 异常已降级、ERROR 局部失败 |
| 时间戳 | `YYYY-MM-DD HH:MM:SS.SSS`，**本地时间，不含时区** |
| 格式 | `YYYY-MM-DD HH:MM:SS.SSS  级别  trace_id  线程ID或进程ID  模块:行号 - 日志内容`（逐字一致，不得增删字段） |
| 编码/语言 | 统一 UTF-8、中文 |
| 输出 | 文件 + 终端；文件默认 `项目根目录/logs/` |
| 命名 | `项目名-YYYYMMDD.log`，即 `logs/dbdlp-YYYYMMDD.log` |
| 轮转 | 按日轮转，**每日一文件，保留 32 天**，自动清理过期 |
| 脱敏 | 遵循第 14.2 章；**禁止记录：密码、完整身份证号、手机号**；IP 按 `*.*.10.3` 处理 |
| 错误 | 统一中文，禁打印明文密码 |

格式示例：
```text
2026-11-13 22:14:03.127  ERROR  18432  scan/run_task.go:96 - 数据源连接测试失败：主机不可达，请检查地址与端口
2026-11-13 22:14:05.402  WARN   18432  engine/rule_loader.go:41 - 规则 MOBILE_PHONE 未启用，已跳过
```

实现约束：
- `模块:行号` 由日志封装经 `runtime.Caller` 取调用点，禁手写字符串。
- 写入前统一过 `sanitize` 对消息与结构化字段同时脱敏；禁业务代码绕过 `Logger` 直连 `fmt.Println`。
- 轮转清理在每日首个日志事件惰性执行，删 mtime 超 32 天的 `dbdlp-*.log`；删除失败记 WARN，不影响主流程。
- DEBUG 可打印采样统计与命中摘要，但**任何级别都不得打印样本原值**。

## 10. 持久化

### 10.1 形态

- 默认 SQLite，`data/dbdlp.db`，**WAL 模式**；驱动 `modernc.org/sqlite`（纯 Go，`CGO_ENABLED=0` 交叉编译）。
- DSN：`file:data/dbdlp.db?_pragma=journal_mode(WAL)&_pragma=foreign_keys(1)&_pragma=busy_timeout(5000)&_pragma=synchronous(NORMAL)`，`_pragma` 每连接生效。
- `SetMaxOpenConns(1)`/`SetMaxIdleConns(1)`：SQLite 单写者避 `database is locked`。
- 可选 PostgreSQL：仅换 `Store` 适配器，DDL 按 10.4 转换，业务层零改动。
- 所有表含 `id`/`created_at`/`updated_at`；软删除用 `deleted_at`（NULL 未删）。时间统一 `TEXT`，格式 `YYYY-MM-DD HH:MM:SS.SSS`，与日志一致。

### 10.4 PostgreSQL 差异（切换后端时转换）

| SQLite | PostgreSQL |
|---|---|
| `TEXT PRIMARY KEY` | `TEXT PRIMARY KEY`（UUID 字符串一致） |
| `INTEGER`（布尔） | `BOOLEAN`（`0/1`→`false/true`） |
| `TEXT`（时间） | `TIMESTAMP(3)` 或保持 `TEXT` |
| `TEXT`（JSON） | `JSONB` |
| `REAL` | `DOUBLE PRECISION` |
| `PRAGMA journal_mode=WAL` | 不适用（PG MVCC） |
| `SetMaxOpenConns(1)` | 按 `storage.max_open_conns` 设池 |
| DSN `?` | pgx `$1`；仓储 SQL 经 `Driver.Placeholder` 或 PG 专用实现 |

### 10.5 迁移方案

- `migration.go` 维护有序版本号列表，启动时读 `PRAGMA user_version` 比对，按序执行增量 DDL，成功更新版本号。
- 每次迁移在事务内执行；失败回滚并中文告警，禁带伤启动。
- MVP 不做破坏性迁移；确需变更时新增列 + 双写 + 后续版本清理。

## 12. 采样与限流

### 12.1 采样量（总纲硬规定）

- **每列默认抽样 20 行**，主键范围分页；`scan.sample_rows` 可配 1~1000，默认 20。
- v1.0「小表 500~1000 / 中表 200~500 / 大表 100~200」分级采样**作废**。
- 自适应采样列后续增强，本期不实现。

### 12.2 主键范围分页

```text
last_key = 检查点值（无则空）
loop:
    SELECT <columns> FROM <schema>.<table>
     WHERE <pk> > <last_key> ORDER BY <pk> ASC
     LIMIT/FETCH FIRST <batch_size> ROWS ONLY;
    逐行流式 Scan，CLOB/TEXT 截断 max_text_len，BLOB 跳过；
    last_key = 本批最大主键；写检查点；
    if 本批行数 < batch_size 或 累计 >= sample_rows 或 HasMore=false: break;
    sleep(batch_interval_ms);
```

- 禁止深偏移 `OFFSET n`；分页语法由方言适配器生成（5.3）。
- 无主键表：记中文警告，退化为受限行数扫描（不超 `sample_rows`），不做全表遍历，台账 `scan_state=skipped` 写原因。
- 每批独立超时（`query_timeout_ms`），超时计失败批次，有限重试 `retry_max` 后跳过继续。

### 12.3 限流与低峰

| 手段 | 默认值 | 说明 |
|---|---|---|
| 并发度 | 1（可配 1~4） | 信号量控制 |
| 批次间隔 | 50ms（0~2000ms） | 批次间节流 |
| 连接池上限 | 2（每实例） | 只读连接池 |
| 单查询超时 | 30s | 独立超时 |
| 单任务总时长 | 120min | 超限标记部分失败 |
| 低峰窗口 | `22:00-06:00` | 窗口外暂停并写检查点 |
| 流式读取 | 强制 | `Rows.Next()` 逐行，不整体载入内存 |

### 12.4 大表降级与断点续扫

- `est_rows > large_table_rows`（默认 1000 万）或 `is_huge=true`：降级低采样或直接跳过，台账记录依据与中文原因。
- 检查点按 `(task_id, table_meta_id, column_name)` 唯一，记 `last_key`/`done_rows`；恢复跳 `state=done`，从最近 `last_key` 继续。
- 部分失败对象记入 `scan_task.summary`，支持单任务重试。
- 报告导出走 excelize `StreamWriter` + 分页查询，避内存溢出。

## 13. 前后端接口边界

### 13.1 通用约定

- 所有端点带版本前缀 `/api/v1/`；v1 保持兼容，不兼容变更新增 `/api/v2/`。
- 统一响应：`{ "code": 0, "data": {}, "message": "" }`；`code=0` 成功，非 0 错误；`message` 中文。分页 `data`：`{ "items": [], "total": 100, "page": 1, "limit": 20, "hasMore": true }`。
- 认证：除 `POST /api/v1/auth/login` 外全部需 `Authorization: Bearer <token>`；token 哈希存 `web_session`，服务端不存明文。
- 前端 `services/` 封装调用，`stores/`（Zustand）管状态，`components/ui/`（shadcn/ui）管组件，`components/charts/`（ECharts）管图表；页面只组装不写业务。
- **凭据不出后端**：所有数据源接口响应中 `password` 恒为 `"******"`，`host`/IP 按第 14 章脱敏；前端拿不到明文凭据。
- 控制台静态资源由 Go 同端口托管，同源部署不引跨域配置。

### 13.2 端点清单（共 32 个；与 33 的口径差异源于是否计入各 HTTP 方法同路径——以本表路径行数为准记为 32）

| 路径 | 方法 | 请求 | 响应 `data` | 认证 | 说明 |
|---|---|---|---|---|---|
| `/api/v1/auth/login` | POST | `{username, password}` | `{token, expiresAt, displayName}` | 否 | 失败中文错误；连续失败锁定 |
| `/api/v1/auth/logout` | POST | 空 | `{}` | 是 | 删会话 |
| `/api/v1/auth/me` | GET | — | `{userId, username, role}` | 是 | 当前登录态 |
| `/api/v1/datasources` | GET | `?page=&limit=&dialect=&keyword=&sort=` | `Page[DataSource]` | 是 | 列表筛选排序 |

## 14. 报告层、掩码策略与分级算法

### 14.1 报告形态（总纲：Excel/HTML/JSON 全出）

| 格式 | 实现 | 内容 |
|---|---|---|
| Excel | `excelize/v2`，大结果集 `NewStreamWriter` | 概览/字段台账/命中明细/复核记录/规则清单/任务记录 六 Sheet |
| JSON | 结构化 | 与台账字段一致，供下游；**不含完整明文值** |
| HTML | 模板渲染 | 概况→风险汇总→高/中风险→待复核→加密脱敏现状→整改建议→附录 |

三种格式由 `Reporter` 按 `Format()` 注册工厂，`POST /api/v1/reports` 可一次多格式。共享同一 `ReportBundle`（第 11 章）。报告含实例/模式/表/字段/样本/命中数/风险等级；「样本」仅放脱敏样例。

### 14.2 脱敏策略（硬规定）

| 类型 | 规则 | 示例 |
|---|---|---|
| IPv4 | 前两段 `*` 替换，留后两段 | `192.168.10.3` → `*.*.10.3` |
| 本地回环 | `127.0.0.1`/`localhost` **可保留完整** | `127.0.0.1` 原样 |
| 其他敏感 | `*` 替换（兜底） | 不保留可还原片段 |
| 密码 | 恒固定占位串 | `******` |
| 身份证/手机号/邮箱 | 按类型掩码；日志禁记完整值 | 仅掩码形态 |

适用范围（三处，缺一不可）：1) SQL 输出字面量先脱敏；2) 运行日志全级别含结构化字段；3) 报告文件所有格式样例与明细。补充：报告只放脱敏样例、不放完整明文；明细导出须认证并记审计。

### 14.3 风险分级（`RiskClassifier`）

| 条件 | 风险等级 |
|---|---|
| 明文 + 高敏感（身份证/手机号/银行卡/护照/统一社会信用代码） | `high` |
| 无盐哈希（定长十六进制、无明文格式） | `medium_high` |
| 明文 + 低敏感（人名/地址/公司名，仅元数据辅助） | `medium` |
| 透明加密 / 加盐哈希 | `medium_low` |
| 已掩码 / 已脱敏 | `low` |
| 仅格式命中、Verify 未过、命中率低 | `pending_review` |

分级映射表可按企业标准在规则配置调整；本期不接外部分类分级系统。

### 14.4 置信度（`ConfidenceCalculator`）

```text
hit_ratio = sample_hit / sample_total   （sample_total=0 时恒 0，置信度 low）
high   = Verify 通过 且 列名/注释与类型吻合 且 hit_ratio >= rule.threshold
medium = Verify 通过但列名不吻合；或 未过 Verify 但字节+正则特征强且 hit_ratio 较高
low    = 仅正则命中、未过 Verify、hit_ratio 低
```

`Aggregator.ComputeConfidence` 为唯一入口，禁在 handler/repo 重写。存储形态判定（`StorageFormDetector`）依加密字典标记、定长哈希特征、掩码字符特征、明文格式四类来源。

## 15. 安全设计

| 维度 | 设计 |
|---|---|
| 只读约束 | 只读账号 + `readonly.go` 白名单守卫（双保险）；写操作直接拒绝记 WARN |
| 凭据保护 | `ENC(base64)` 存储；明文仅内存瞬时；API 返占位串；密钥 0600；失败终止进程 |
| 数据最小化 | 每列 20 行；CLOB 截断；BLOB 跳过；只拉采样所需列 |
| 明文保护 | `Hit` 不含 `RawValue`；`Candidate.Raw` 引擎内瞬时用后即弃；落库/日志/报告只掩码值 |
| 日志与报告脱敏 | 见 14.2；三处强制 |
| 访问控制 | 全端点需 Bearer（登录除外）；密码 Argon2id/bcrypt 哈希；连续失败递增锁定记审计 |
| 会话安全 | 只存 token 哈希、设 `expires_at`、登出即删；默认仅 `127.0.0.1` |
| 审计留痕 | 数据源增删改/批量导入/任务启停/复核/报告导出全写 `audit_log`，含操作者/时间/结果/脱敏 IP |
| 输入校验 | handler 层校验；标识符经 `QuoteIdentifier`；参数占位符绑定，禁字符串拼接 |
| 传输与存储 | 内网离线；远程须显式配置并启用 TLS；存储库最小权限 |
| 错误处理 | 全中文；对外不回显堆栈/连接串/密钥路径 |

## 16. 错误处理与降级

| 场景 | 处理 | 中文错误示例 |
|---|---|---|
| 连接失败/测试未通过 | 标记实例失败，**不保存配置**，不影响其他 | 「连接测试未通过：账号或密码错误，配置未保存」 |
| 密钥不可用 | **直接终止进程**，不回退默认密钥 | 「密钥读取失败，进程已终止」 |
| 规则加载失败 | 任务拒绝启动 | 「规则文件校验失败：正则无法编译」 |
| 单表查询超时/报错 | 计失败表，有限重试后跳过 | 「表 X 查询超时，已跳过并记录」 |
| 字段类型不支持 | 记跳过原因，`scan_state=skipped` | 「二进制字段，未扫描」 |
| 引擎识别异常 | 单字段降级「未识别」，不中断任务 | 「字段 X 识别异常，已降级为未识别」 |
| 存储写入失败 | 内存批次重试；仍失败落本地应急文件，标记 `partial_failed` | 「台账写入失败，已保留本地应急文件」 |
| 大表资源风险 | 按阈值降级或跳过 | 「表 X 估算行数超过阈值，已降级为低采样」 |
| 无主键表 | 受限行数扫描 + WARN | 「表 X 无主键，已退化为受限扫描」 |
| 控制台未认证/过期 | 401 + 中文错误 | 「登录状态已失效，请重新登录」 |

原则：单对象失败不阻断整体；所有失败可追溯、可重试；错误全中文且不含敏感值。

## 18. 部署形态

```text
  ┌────────────────────────────────────────────┐
  │  dbdlp 单二进制（Go，CGO_ENABLED=0）          │
  │  ├─ interfaces/http  托管 web/out + /api/v1  │
  │  ├─ interfaces/cli   scan/report/retry/serve/datasource │
  │  ├─ application / domain / infrastructure    │
  └───────┬──────────────┬────────────┬─────────┘
          ▼ 只读SQL        ▼ 文件       ▼ 文件
  ┌────────────┐  ┌──────────────────┐  ┌────────────┐
  │ Oracle/达梦 │  │ data/dbdlp.db(WAL)│  │ reports/   │
  │ （首批5种） │  │ logs/ .dbdlp/key  │  │ Excel/HTML/│
  │            │  │ dbdlp.toml rules  │  │ JSON       │
  └────────────┘  └──────────────────┘  └────────────┘
```

- **MVP**：单机、SQLite WAL、命令行 + 同源 Web 控制台（默认 `127.0.0.1:8080`），一二进制 + 配置文件即可运行。
- **企业部署**：`storage.driver=postgres` 切服务端库；控制台可置反向代理后并启用 TLS。
- **离线构建**：`CGO_ENABLED=0 go build` 产单二进制；excelize/modernc.org/sqlite/gmsm/go-ora/v2 均纯 Go；规则 YAML/TOML 随包发布，运行时不依赖外网。
- **信创**：达梦首批方言；`chunanyong/dm` 纯 Go，无需达梦客户端动态库。
- **目录权限**：`data/`/`logs/`/`.dbdlp/` 仅运行账号读写；`.dbdlp/key` 0600。

运行命令：
```bash
./dbdlp scan --config-dir . --data-source ORA-PROD-01 --sample-rows 20
./dbdlp datasource add --name ORA-PROD-01 --dialect oracle --host <ENC 或交互输入> --test
./dbdlp resume --task <task_id>
./dbdlp retry --task <task_id>
./dbdlp report --task <task_id> --formats excel,html,json --out reports/
./dbdlp serve
```

> v1.0 三份 YAML（`instances.yaml`/`scan.yaml`/`rules.yaml`）已合并为 `dbdlp.toml` 统一入口；规则独立保留 `configs/rules.yaml`。
