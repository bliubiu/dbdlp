# 开发计划与任务拆解

> 版本：v1.0 ｜ 日期：2026-11-13 ｜ 维护者：项目总监（编排层）
> 依据：`03-规格契约Spec.md` 为唯一契约；`01` PRD、`02` 架构、`04` 前端、`07` 测试、`09` 运维为执行依据。
> 前提：**本次迭代只交付文档，代码实现尚未开始**。本计划是文档落地后的开工路线，非已完成清单。

## 1. 计划定位与前提

- 以规格契约为唯一依据，凡不在契约第 2 章范围的能力一律不做，新增需求走契约变更流程。
- 测试驱动开发：每模块先落测试用例（见 07 文档），再写实现，最后跑门禁。
- 四层 DDD＋整洁架构：依赖只向内，`domain` 不依赖外层；单文件 ≤ 300 行；入口只装配不写业务。
- 双周交付可用增量，每增量须带可核验证据（构建、类型检查、测试、静态检查实际输出）；全程中文，禁凭记忆写第三方库接口。

## 5. 质量门禁

| 阶段 | 门禁 | 不通过后果 |
|---|---|---|
| 需求与文档 | 用户确认基线 → 三文档一致性 → 规格契约锁定 | 不得开工 |
| 每模块自检 | lint → 类型检查 → 单测 → 修复，最多 3 轮 | 退回重做 |
| 代码组织 | 目录分层（依赖只向下）、单文件 ≤ 300 行、入口只装配、逻辑下沉 service | 退回重做 |
| 前端 P0 扫描 | emoji 功能图标、紫粉渐变、硬编码色值、图标导出名、模板味文案 | 零容忍，立即替换 |
| 安全 | 只读 SQL 核查、报告／日志无完整明文、凭据不入库不进日志、密钥失败终止 | 阻断放行 |
| 集成 | 端点契约测试、EARS 20 条、强校验基线回归集 | 不得进入部署 |
| 放行 | 07 文档生产就绪评分卡、P0 缺陷归零 | 不得发布 |

## 7. 迭代节奏与交付证据

- 双周一个可用增量，输出：可运行构建、测试报告、lint／类型检查输出、变更记录。
- 模块完成后更新状态，并在 `CHANGELOG.md` 按 CalVer `YYYY.MM.DD.MICRO` 记录；稳定分支 Tag 仅正式发布时创建。
- 决策留痕：新增选型或推翻结论时追加 ADR 到 `docs/decisions/`；踩坑按增量追加到 `.workbuddy/memory/pitfalls.jsonl`，并为阻断项落持久回归用例。
