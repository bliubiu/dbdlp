## 1. 配置体系总览

### 1.1 `dbdlp.toml` 唯一入口与三级优先级

- 唯一运行入口：`项目根目录/dbdlp.toml`；文件缺失时全字段走默认值，进程可启动。
- 优先级（不可协商）：**命令行参数 ＞ `dbdlp.toml` ＞ 内置默认值**。
- `--config-dir <目录>` 指定配置目录，影响 `dbdlp.toml`、`.dbdlp/key`、`configs/rules.yaml`；`dbdlp.toml` 的 `config_dir` 键与之等效（见 3.2）。
- 规则独立存 `configs/rules.yaml`（由 `[engine].rules_file` 指向），是**规则数据**非运行参数，不受三级优先级覆盖。
- `GET /api/v1/config` 只只读回显 `{logLevel, sampleRows, storageDriver, cryptoAlgorithm, retentionDays}`，**不含密钥与 DSN**，不接受写入。

## 2. 凭据加密

### 2.1 `ENC(base64)` 完整载荷布局

敏感配置以 `ENC(<base64>)` 存储，加载自动解密、保存自动加密。载荷布局顺序固定、**无额外头部**（总纲、`02` 第 7.1、ADR-003 一致）：

```text
存储形态：  ENC(Base64(载荷))
载荷字节序（顺序固定）：
  [0]            算法标签 1 字节
  [1..12]        nonce 12 字节（crypto/rand 独立生成）
  [13..N-17]     密文（AEAD Seal，长度=明文长度）
  [N-16..N-1]    认证 tag 16 字节
最短合法载荷 = 1 + 12 + 0 + 16 = 29 字节；短于此直接判非法。
```

硬约束：同一密钥下**严禁复用 nonce**；tag 失败即报错，**绝不返回部分明文**；载荷长度、Base64、标签合法性解密前依次校验，任一失败走 2.6。

### 2.2 算法标签路由

| 标签 | 算法 | 密钥使用 | 本期状态 |
|---|---|---|---|
| `0x00` | AES-256-GCM | **完整 32 字节** | 主选默认（`aes256gcm`） |
| `0x01` | SM4-GCM | **前 16 字节** | 本期落地；`sm4.NewCipher`+`cipher.NewGCM` 已核实（`02` 第 3 章第 8 条） |
| 其它 | — | — | **直接报错终止**，不猜测、不回退、不当明文 |

加密：选标签 → 已是 `ENC()` 则跳过（防循环）→ 生成 12B nonce → `Seal` → 拼接「标签+nonce+密文+tag」→ Base64 → 包 `ENC()`。解密：识 `ENC()` → Base64 → 读标签 → 取密钥相应长度 → `Open` → 校验 tag → 返回明文（仅内存）；**非 `ENC()` 按明文原样返回**。国密切换边界：本期 `0x01` 仍是 SM4-GCM；切换须新增标签（保留旧解密）、核实 API、兼容回归、新 ADR（U-02）。端口签名（`02` 第 11 章，不得改名）：

```go
type Cipher interface {
    Encrypt(plaintext string, alg Algorithm) (string, error)
    Decrypt(stored string) (string, error)
    IsEncrypted(s string) bool
}
type Algorithm byte
const ( AlgAES256GCM Algorithm = 0x00; AlgSM4GCM Algorithm = 0x01 )
```

### 2.3 密钥首次生成流程与 `0600` 权限

| 项 | 规定 |
|---|---|
| 生成 | 首次运行 `crypto/rand` 生成 **32 字节**写入密钥文件，禁手工编辑 |
| 存放 | `.dbdlp/key`（二进制），Unix **`0600`**（对应 `key_file_mode=384`）；Windows 当前用户独占 ACL |
| 使用 | AES-256-GCM 用完整 32 字节；SM4-GCM 用前 16 字节 |
| 查找顺序 | `--config-dir` ＞ 项目根 `./.dbdlp` ＞ `~/.dbdlp`；亦可由 `config_dir` 指定 |
| 轮换 | 本期不自动轮换；需停机旧密钥解密全量后新密钥重加密并原子替换 |
| 单点风险 | 丢失即无法解密已存凭据，须纳入备份；多实例共享存储库须共享同一密钥文件 |

生成时序：① 解析路径得 `Path()`；② `KeyStore.LoadOrInit()`；③ 不存在→生成 32B→`0600` 创建→回读校验→返回；④ 存在→读→校验恰 32B→校验权限未被放宽（放宽记 WARN 并终止）→返回；⑤ 任一步 error→调用方**终止进程**中文错误。签名：

```go
type KeyStore interface {
    LoadOrInit() ([]byte, error)  // 首次生成 32B 并以 0600 写入；任何失败返回错误，调用方必须终止
    Path() string                 // 返回密钥文件路径（用于启动日志，路径不含敏感值）
}
```

`KeyStore.Path()` 可用于日志，但**密钥字节、Base64、十六进制摘要一律不得写入任何日志、报告、API 响应**。

### 2.4 自动加解密时机

| 时机 | 动作 | 约束 |
|---|---|---|
| 新增／修改写入前 | `Encrypt` 把 `password`、`host`、连接串敏感片段加密为 `ENC(...)` | 事务边界内完成，禁明文先落库再补加密 |
| 读取时 | `Decrypt` 自动解密仅用于建连 | 明文仅内存短时存在，不落日志／报告／前端 |
| `data_source` 写入时 | 敏感字段一律 `ENC(...)` | 见第 3、5 章 |
| `dbdlp.toml` `postgres_dsn` | 须 `ENC()` 或环境变量引用 | 禁明文落盘 |
| 批量导入逐条 | 每条独立加密、独立 nonce | 禁全批复用 nonce |
| API 响应 | 密码恒 `"******"`；`host`/IP 脱敏 | `02` 第 13.1「凭据不出后端」 |

明文存活限定在 `DataSourceConfig.Password` 从解密到 `Connect` 之间；建连后不得保留在长生命周期结构／缓存／日志。

### 2.5 `ENC()` 识别与循环加密防护

- 写入路径先 `IsEncrypted(value)`；`true` 则**跳过加密**，绝不 `ENC(ENC(...))`（这是「凭据留空表示不修改」正确工作的前提）。
- 解密路径自动识 `ENC()`；非 `ENC()` 按明文原样返回，兼容非敏感字段。
- 合法 `ENC()` 须含前缀、Base64 可解码、载荷 ≥ 29 字节三项；仅前缀匹配而内容非法按 2.6 报错。
- 回归用例须覆盖：明文↔ENC 往返；ENC 再次入写入路径不被二次加密；`0x00`/`0x01` 双向可解；非 ENC 原样返回；截断／篡改密文失败且不产部分明文。

### 2.6 密钥不可用与环境变量无效的终止策略（绝不回退）

任一情形**直接报错终止进程**，**绝不回退默认／全零／临时密钥，绝不降级明文**（`02` 第 7.3、ADR-003、`2003`）：

| 情形 | 判定 | 中文错误（不泄露明文） | 码／HTTP |
|---|---|---|---|
| 密钥不存在且无法创建 | `LoadOrInit` error | 「密钥文件不可用，进程已终止」 | `2003`/500 |
| 密钥损坏／解码失败 | 读取校验失败 | 「密钥读取失败，进程已终止」 | `2003`/500 |
| 长度非 32 字节 | 长度校验失败 | 「密钥长度不合法，进程已终止」 | `2003`/500 |
| 权限不足／被放宽 | 权限校验失败 | 「密钥文件权限不合法，进程已终止」 | `2003`/500 |
| 环境变量引用无效 | 解析失败 | 「凭据环境变量不可用，进程已终止」 | `2003`/500 |
| 密文标签未识别 | 路由失败 | 「密文算法标签不支持，配置未加载」 | `2003`/500 |
| tag 校验失败／被篡改 | `Open` error | 「凭据密文校验失败，配置未加载」 | `2003`/500 |

环境变量引用语法在 `02` 未定义，标「待验证」，解析失败一律走本表。终止必须由调用方执行，任何错误不得 catch 吞掉后继续。对外 message 一律中文，不回显堆栈／连接串／密钥路径／明文／密文片段。

### 2.7 密文存放形式与 `data_source` DDL

### 2.8 错误提示中文且不泄露明文

| `username` | TEXT | NOT NULL | 只读账号名 |
| `password_enc` | TEXT | NOT NULL，`ENC` | 密码 |
| `dsn_enc` | TEXT | 可空，`ENC` | 完整连接串（可选） |
| `include_schemas` | TEXT | JSON 数组 | 为空扫非系统模式 |
| `exclude_tables` | TEXT | JSON 数组 | 排除表 |
| `exclude_columns` | TEXT | JSON 数组 | 排除字段 |
| `conn_max_open`/`conn_max_idle` | INTEGER | DEFAULT 2/1 | 实例池 |
| `conn_timeout_ms`/`query_timeout_ms` | INTEGER | DEFAULT 10000/30000 | 实例超时 |
| `last_test_at` | TEXT | 可空 | 最近测试时间 |
| `last_test_ok` | INTEGER | DEFAULT 0 | 最近是否通过 |

| `remark` | TEXT | 可空 | 备注 |

索引：`idx_data_source_dialect ON dialect`、`idx_data_source_deleted ON deleted_at`。审计表 `audit_log`：`id`(UUID)、`actor`、`action`(`datasource.create/update/delete/enable/disable/import/test` 等)、`target_type`/`target_id`、`detail`(JSON 已脱敏)、`result`(`success`/`failed`)、`error_message`(中文)、`ip_masked`、`created_at`/`updated_at`。存储端口（`02` 第 11 章，不得改名）：`CreateDataSource`/`UpdateDataSource`/`DeleteDataSource`/`GetDataSource`/`ListDataSources(ctx,f)(Page[DataSource],error)`/`BatchCreateDataSources(ctx,items) error`（注释「整批事务语义、导入不调用」）/`AppendAudit(ctx,a) error`。

**施工注意（D8）**：批量导入**不调用** `BatchCreateDataSources` 整批事务，改为逐行 `CreateDataSource` 独立事务，通过入库、失败不入库；不得用它实现部分成功（否则一行失败拖垮全批）。

### 5.2 唯一约束与校验规则

| 规则 | 判定 | 失败处置 |
|---|---|---|
| `name` UNIQUE | 新建/改名/导入与全表（含软删除行）比对 | 中文「数据源名称已存在，请更换名称」，不覆盖 |
| `name` 格式 | `^[A-Za-z0-9_-]{2,64}$` | 字段级错误 |
| `dialect` 枚举 | 仅 `oracle`/`dameng` 本期可存；其余占位保存拒绝 | 1001「该方言本期未实现适配器」 |
| `host`/`password` | 写入前须合法 `ENC(...)`、非空 | 中文「凭据加密失败，配置未保存」，不落库 |
| `port` | 1~65535 | 字段级错误 |
| `service_name` | 非空、≤128 | 字段级错误 |
| `username` | 非空、只读账号 | 字段级错误 |
| `include/exclude_*` | 合法 JSON 数组；排除正则须可编译 | 中文「排除规则语法不合法」 |
| 池/超时字段 | 正整数，范围见 4.3/4.4 | 字段级错误 |

**`name UNIQUE` 与软删除陷阱**：`UNIQUE` 全表唯一，软删除行仍占名；「删除后以同名新建」会撞约束。本期不擅改 DDL；应用层查重纳入软删除行，命中给「该名称已被已删除的数据源占用，请更换名称或由运维恢复」（5.2）；如需「同名可重建」须总监裁定另立 ADR 改部分唯一索引。

### 5.3 五个完整流程

统一前置：除 login 外全需 `Authorization: Bearer <token>`；统一响应 `{code:0,data:{},message:""}`（message 中文）；分页 `data` 固定 `{items:[],total:100,page:1,limit:20,hasMore:true}`。

**5.3.1 查询（Read）**
```
GET /api/v1/datasources?page=&limit=&dialect=&keyword=&sort=  → Page[DataSource]
GET /api/v1/datasources/{id}                                  → DataSource
```
默认分页；排除 `deleted_at` 非空；`password` 恒 `"******"`，`host`/IP 脱敏，不返 `dsn_enc` 解密值；排序默认「连接异常优先，其次最近扫描倒序」；`keyword` 只匹配名称与账号名。

**5.3.2 新增（Create）**
```
POST /api/v1/datasources  → {name,dialect,host,port,serviceName,username,password,includeSchemas,...}  → {id,lastTestOk}
```
① 参数与唯一性校验（5.2），失败 1001 不测；② 执行 3.6 时序，失败 2001 整条不落库；③ `Encrypt` 加密 host/password/可选 dsn；④ 单事务写 `data_source`(`last_test_ok=1` 等)+`audit_log`(create,success)；⑤ 返回 `{id,lastTestOk:true}`。判定：`POST` 即「先测后存」，不另设无 id 测试端点（D4）。

**5.3.3 修改（Update）**
```
PATCH /api/v1/datasources/{id}  → {可改字段}  → {id}
```
回填走 GET；凭据字段「已配置，留空表示不修改」，留空不碰 `password_enc`（依赖 2.5）；**含凭据或任一连接字段变更须重新通过连接测试**，失败 2001 保持原值不产生半条；仅改扫描范围不强制重测仍做 JSON/正则校验；改名重走唯一性（含软删除）；成功写 `audit_log`(update，detail 记字段名不记值)。

**5.3.4 删除（Delete）与软删除策略**
```
DELETE /api/v1/datasources/{id}  → {}
```
① 控制台二次确认；② 服务端内部引用检查（D6）：运行中任务时拒绝中文提示；有历史/报告转软删除；③ 软删除 `UPDATE ... SET deleted_at=?,enabled=0,updated_at=?`，**不执行 DELETE FROM**；④ `audit_log`(delete,success)；⑤ 返回 `{}`，无撤销入口（5.5）。软删除 `deleted_at` 为 NULL 表示未删；时间统一 `TEXT` 本地时间；运行中任务拒绝（`3001`）；审计覆盖失败分支。

**5.3.5 启用／停用**
- 复用 `PATCH` 改 `enabled`（1/0）；停用不删记录、不影响历史；停用数据源不得被 `POST /api/v1/tasks` 选中。
- 每次启停写 `audit_log`(enable/disable)；重测 `POST /api/v1/datasources/{id}/test` 只读探针不改动配置，返回 `{ok,latencyMs,message}` 并更新 `last_test_at`/`last_test_ok`。

### 5.5 审计留痕与「有扫描历史不得物理删除」

`02` 第 10.2 ER：`data_source ─1:N─ scan_task ─1:N─ finding_column ─1:N─ finding_hit`，外键关联 `data_source(id)`；物理删除破坏外键与历史可追溯性。策略：① **一律软删除**，保留行与全部历史外键；② 列表默认排除 `deleted_at` 非空，历史仍可按 `data_source_id` 关联名称；③ 不提供物理删除/恢复端点，确需恢复由运维操作并记入手册；④ `audit_log` 记动作/`actor`/时间/`result`/脱敏 `ip_masked`，`detail` JSON 已脱敏；⑤ 软删除行仍占 `name` 唯一，查重须覆盖（5.2）。

### 6.2 校验规则（四层，`04` 第 3.5）

| 层 | 校验项 | 回显位置 |
|---|---|---|
| 文件级 | 扩展名、单文件 ≤10MB、行数 ≤5000、编码、Sheet 名、YAML 语法 | 上传区顶部 Alert |
| 行级 | 必填、主机格式、端口、标识格式、模式合法、排除正则、文件内重复 | 预览行状态 + 行内错误 |

失败回显四要素（**错误分类+具体字段+当前值(脱敏)+可操作建议**），禁只显示「导入失败」；错误清单结构化含行号。

### 6.3 逐条门禁与部分成功策略（D8，总监裁定）

**本期：逐条门禁 + 部分成功，不整批回滚。** 依据：`02` 第 7.5/13.2/21 A7 与 ADR-002/003 已对齐统一裁定（DIFF-01）；import 响应体 `{total,succeeded,failed,errors}` 即部分成功结构；`03` 规格契约第 5 章为唯一裁定依据。

| 场景 | 门禁 | 事务 | 结果 |
|---|---|---|---|
| 单条 `POST /datasources` | 先测后存 | 单条独立 | 失败整条不落库 |
| 含凭据 `PATCH` | 须重测 | 单条独立 | 失败保持原值 |
| 批量 `POST /datasources/import` | **逐条**测+逐行校验 | **逐条独立** | 通过入库、失败不入库，允许部分成功 |

响应语义：`total=succeeded+failed` 恒成立；全批通过 `code=0` 写 total 条；部分成功 `code=0` 仅写通过行；全批失败 `code=2001` 零写入。`partial` 状态=部分成功（正常业务结果非降级）。冲突三策略（跳过/覆盖/报错）保留为逐行判定输入；「覆盖」写库实现列后续。重复导入按幂等键去重；**失败行可导出错误清单仅重试失败行**。单失败行：不留半条、不写成功审计（可写 failed 留痕）、不影响其它通过行。

### 6.4 错误行回显格式

统一中文、不含明文凭据：
```json
{ "code":0, "data":{ "total":3, "succeeded":1, "failed":2,
  "errors":[ {"row":2,"message":"连接测试未通过：主机不可达，请检查地址与端口；该行未入库"},
             {"row":3,"message":"实例标识已存在（含已删除记录），请更换名称；该行未入库"} ] },
  "message":"批量导入完成：成功 1 行、失败 2 行，失败行未入库，可导出错误清单修正后重试" }
```
约束：`code=0`/HTTP 200，`total=succeeded+failed`；message 与 errors 含分类+字段+建议；不出现明文密码/连接串/密文/堆栈/密钥路径；IP 回显按 `*.*.10.3`（`127.0.0.1`/`localhost` 保留）；错误清单不含凭据列。

### 6.5 导入幂等与去重

- 唯一键 `name`（`UNIQUE`）；文件内重复与库内（含软删除）重复均判冲突进 `errors`。
- 幂等键=「文件内容摘要 + 提交行号集合」；相同键重复提交直接返首次结果。
- 前端提交 `loading` 禁用防重复；服务端不依赖前端勾选，提交时**重新全量校验与逐条测试**（6.3）。
- 每条凭据独立 `Encrypt`、独立 nonce（2.1），禁全批复用。

### 6.6 大文件流式读取避免内存溢出

- 硬性上限（04 第 3.5）：单文件 **≤10MB**、**≤5000 行**；超限拒并中文「文件超过 5000 行上限，请拆分后重新上传」。
- 逐行处理：解析即校验即丢明文凭据引用，只留脱敏预览；禁整文件读成大对象。
- 逐条连接测试并发上限 **2**（对齐 `scan.concurrency` 低侵入）。
- **excelize/YAML 签名边界（禁凭记忆）**：`02` 第 7 条已核实 excelize `NewFile`/`NewSheet`/`SetCellValue`/`OpenFile`/`GetRows`(全量读)/`NewStreamWriter`(流式写)；**大文件流式逐行读迭代器 API 未核实，标「待验证」**；YAML 解析库及 `Decoder` 未核实标「待验证」；`excelize` 须选 **Go ≤ 1.25.10** 的 tag 标「待验证」；Go 工具链保持 **1.25.10 不提升**。核实前兜底：Sheet 分片 + 行数/大小上限 + 逐行释放，保证峰值内存有界；**不得**用未核实 API 顶上。

| 数据合规 | `ENC(base64)`；`0600`；三处强制脱敏；日志禁记密码/身份证/手机号 |
| 幂等并发 | 批次幂等键+逐行去重；`name` 唯一；SQLite 单写者 `max_open_conns=1`；逐条事务+部分成功（6.3） |
| 审计 | 增删改/导入/连接测试/任务/复核/报告导出全写 `audit_log` |

### 7.6 前端技术栈边界（只复述约束，不锁版本）

- 按总纲：TypeScript 7.0+/Next.js 16.2+ App Router/React 19.2+/Tailwind/ECharts/Zustand/shadcn/TanStack Table；前端仅 `/api/v1/*` 取数，不直连被监控库或存储库；静态导出 `web/out` 同源托管。
- **Zustand 精确版本标「待验证」**（D12），不写死；图标只文字语义描述，不用 emoji 作功能图标，不引第二套图标库、不硬编码颜色、不用紫粉渐变；图标库版本差异提请总监统一。

## 8. 配置错误与降级、故障处置、参考依据

### 8.1 配置错误分层与处置

| 层 | 触发 | 码/HTTP | 处置 |
|---|---|---|---|
| 第一层：参数校验 | 类型/范围/枚举不合法、未识别键、模板必填缺失 | `1001`/400 | 中文+终止启动或拒请求；**未识别键终止启动**（1.4） |
| 第二层：业务规则 | 连接测试失败、名称冲突、任务占用、密钥不可用 | `2001`/`422`、`2003`/500、`3001`/409 | 单条失败不落库；批量失败行不入库、通过行照常（部分成功）；中文建议 |
| 第三层：全局异常 | 未分类错误、存储写入失败 | `5000`/500、`3002`/500 | 中文日志（脱敏），对外不回显堆栈/连接串/密钥 |

### 8.2 降级边界（哪些绝不降级）

| 场景 | 允许降级？ | 说明 |
|---|---|---|
| 密钥不可用 | **绝不** | 终止进程，绝不回退默认/全零/临时密钥/明文（2.6） |
| 连接测试未通过 | **绝不** | 不保存、不留半条（3.6、A7） |
| 只读守卫触发 | **绝不** | 直接拒绝 SQL 记 WARN（4.5） |
| 批量逐条门禁 | **绝不** | 未通过行绝不入库；通过行照常；部分成功非降级（6.3） |
| 配置文件缺失 | 允许 | 全字段走默认值（1.1） |
| 单表查询超时/报错 | 允许 | 重试后跳过（`02` 第 16 章） |
| 字段类型不支持 | 允许 | 记跳过，台账 `scan_state=skipped` |
| 引擎识别异常 | 允许 | 单字段降级「未识别」不中断 |
| 存储写入失败 | 允许 | 内存批次重试，仍失败落应急文件，任务 `partial_failed` |
| 大表资源风险 | 允许 | 按阈值降级采样或跳过，记依据 |
| 无主键表 | 允许 | 受限行数扫描+WARN，不做全表遍历 |

原则：**凭据安全、落库正确性、只读边界三类路径不降级**；扫描完整性与性能路径可降级且须留中文依据。

### 8.3 常见故障处置表

| # | 现象 | 原因 | 处置 | 中文提示 |
|---|---|---|---|---|
| 1 | 启动退，未识别配置项 | toml 键拼错 | `Undecoded()` 拦截，修正重启 | 「未识别的配置项，请核对 dbdlp.toml 字段表」 |
| 2 | 启动退，密钥相关 | 缺失/损坏/非32B/权限放宽 | 运维恢复或重初始化（已存密文不可解） | 「密钥读取失败，进程已终止」 |
| 3 | 凭据环境变量无效 | 缺失/空/语法未定 | 终止；定案后配 | 「凭据环境变量不可用，进程已终止」 |
| 4 | 解密失败 | 篡改/标签未知/载荷<29B | 拒加载不回退明文 | 「凭据密文校验失败，配置未加载」 |
| 5 | 新增失败无记录 | 连接测试未通过 | 按分类整改重试，确认表无新增 | 「连接测试未通过：主机不可达，配置未保存」 |
| 6 | 达梦异常参数无误 | `COMM_ENCRYPT_NAME=AES128_ECB` | 与 DBA 确认；字段名勿加双引号 | 「连接测试未通过：驱动或版本不兼容，配置未保存」 |
| 7 | Oracle 导入路径错 | 不带 `/v2` | `go.mod` 改 `github.com/sijms/go-ora/v2` | 「驱动初始化失败，请核对导入路径」 |
| 8 | 编辑后双重 ENC | 写入未做识别 | `IsEncrypted` 跳过；补回归 | 「凭据格式异常，配置未保存」 |
| 9 | 同名新建失败 | `name UNIQUE` 软删除占名 | 换名或运维恢复（5.2） | 「该名称已被已删除的数据源占用，请更换名称」 |
| 10 | 删除被拒绝 | 运行中任务 | 先停任务 | 「任务正在运行中，不能重复启动」语义拒绝 |
| 11 | 批量部分行未生效 | 部分行校验/测试失败 | 导出错误清单仅重试失败行；幂等去重 | 「批量导入完成：成功 M 行、失败 N 行，失败行未入库」 |
| 12 | 大文件内存涨 | 全量读或超行数 | 守 ≤10MB/≤5000 行；核实流式签名（6.6） | 「文件超过 5000 行上限，请拆分后重新上传」 |
| 13 | 本地库 `database is locked` | 本地池误设>1或误用被监控池 | 恢复 `max_open_conns=1`，确认两池未共用（D10） | 「台账写入失败，已保留本地应急文件」 |
| 14 | 控制台 401 | 会话过期/token 无效 | 重新登录 | 「登录状态已失效，请重新登录」 |
| 15 | 日志明文风险 | 绕过 Logger 直输 | 统一 `sanitize`，任何级别不打印样本 | 内部门禁失败 |
| 16 | 报告/IP 全段 | 脱敏未覆盖 | 按 `*.*.10.3` 补脱敏 | 内部门禁失败 |
