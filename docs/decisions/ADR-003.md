# ADR-003: 凭据加密方案与密钥管理

## Status

Accepted（2026-11-13）

## Background

v1.0 架构文档对凭据保护只写「密码 / 凭据引用：支持配置文件引用或凭据托管，禁止明文写死在报告中」，没有加密方案、没有载荷格式、没有密钥管理，也没有「密钥不可用」时的行为定义；安全章节仅给了四类掩码样例。该状态无法满足总纲「安全与约束」节的硬要求，也无法支撑本期新增的网页控制台（数据源配置写入后端存储库、可增删改查与批量导入）——凭据一旦落库，就必须有明确的加密与密钥方案。

总纲相关条款：

- 第 204 行：数据库敏感数据（如密码、IP 地址）以 `ENC(base64)` 格式加密存储，**加载时自动解密、保存时自动加密**，无需人工干预。
- 第 223 行：首次运行自动生成 **32 字节**随机密钥并保存到密钥文件（Unix 权限 **0600**），禁止手工编辑；**AES-256-GCM 使用完整 32 字节，SM4-GCM 使用前 16 字节**。
- 第 229~231 行：统一数据库连接信息配置文件，**当且仅当连接测试验证成功时保存，失败则抛出错误信息**。
- 第 238~243 行：IPv4 `192.168.10.3` → `*.*.10.3`，`127.0.0.1` 与 `localhost` 保留完整，其余用 `*` 替换；SQL 字面量、运行日志、报告文件均需脱敏。
- 总纲注明国密侧「SM4-GCM-SIV **待库支持后切换**」。

本轮项目总监下发的施工规格进一步明确：`ENC(base64)` 载荷布局为「算法标签 1 字节 + nonce 12 字节 + 密文 + tag 16 字节」，`0x00` = AES-256-GCM、`0x01` = 国密 SM4-GCM；解密自动识别 `ENC()`；**密钥获取失败直接终止，绝不回退默认密钥**；

联网核实结论（架构文档第 3 章）：`emmansun/gmsm` 的 `sm4.NewCipher(key) (cipher.Block, error)`（16 字节密钥）+ `cipher.NewGCM(block)` 是已核实可直接施工的 SM4-GCM 用法；gmsm 0.44.0+ 已在 `cipher` 包新增通用 GCM-SIV（RFC 8452）能力，但具体导出构造函数签名本轮未从 pkg.go.dev 核实到 → 列入未决项 U-02，本期不切换。

## Decision

**采用 `ENC(base64)` 信封格式 + 算法标签路由 + 32 字节独立密钥文件，密钥失败即终止；数据源凭据在写入存储库之前自动加密，读取时自动解密且明文仅内存瞬时存在。**

### 载荷布局（固定，无额外头部）

```text
存储形态：  ENC(Base64(载荷))
载荷字节序：
  [0]           算法标签 1 字节：0x00 = AES-256-GCM，0x01 = SM4-GCM
  [1..12]       nonce 12 字节（每次加密由 crypto/rand 独立生成）
  [13..N-17]    密文（变长，长度 = 明文长度）
  [N-16..N-1]   认证 tag 16 字节（AEAD Seal 追加）
最短合法载荷 29 字节；短于此直接判非法密文。
```

- 加密：按 `dbdlp.toml` 的 `crypto.default_algorithm`（默认 `aes256gcm`）选标签 → 生成 nonce → `Seal` → 拼接 → Base64 → 包 `ENC()`。
- 解密：识别 `ENC()` 包裹 → Base64 解码 → 读第 0 字节 → 按标签选实现 → 取密钥相应长度 → `Open` → 校验 tag；**未识别标签直接报错终止，不猜测、不回退**。非 `ENC()` 输入按明文原样返回（兼容非敏感字段）。
- 同一密钥下严禁复用 nonce；tag 校验失败绝不返回部分明文。

### 密钥管理

| 项 | 规定 |
|---|---|
| 生成 | 首次运行由 `crypto/rand` 生成 **32 字节**随机密钥写入密钥文件，禁止手工编辑 |
| 存放 | `.dbdlp/key`（二进制），Unix 权限 **0600**；Windows 用当前用户独占 ACL |
| 使用 | AES-256-GCM 用完整 32 字节；SM4-GCM 用前 16 字节（总纲第 223 行） || 查找顺序 | `--config-dir` 指定目录 ＞ 项目根 `./.dbdlp` |
| **失败处理** | 不存在 / 权限不足 / 长度非 32 字节 / 解码失败 → **直接终止进程**，输出中文错误；**绝不回退默认密钥、绝不生成临时密钥顶替、绝不降级为明文** |
| 轮换 | 本期不提供自动轮换；需停机，用旧密钥解密全量 `ENC()` 字段后以新密钥原子重加密（列入运维手册） |

### 保存与读取

- 数据源新增/修改时，`password`、`host`（IP）、连接串敏感片段在**写入存储库之前**由 `Cipher` 端口加密；`data_source.password_enc` / `host_enc` / `dsn_enc` 只存 `ENC(...)`。
- 读取时自动解密后仅用于建立连接；明文凭据只在内存短时存在，不落日志、不进报告、不返回前端（API 响应中密码恒为固定占位串 `"******"`，IP 按脱敏策略处理）。
- 连接测试门禁（与 ADR-002 共用）：测试通过才保存配置，失败不落库、不写文件系统数据源文件（仅持久化到 `data_source` 表）；批量导入按 `docs/02-架构设计文档.md` 7.5 / 13.2 节的**逐条门禁 + 部分成功**口径执行（逐条独立事务、允许部分成功、失败行不入库且逐行中文回显、重复导入幂等去重、不整批回滚；DIFF-01 裁定）。
- 日志与报告中出现 IP 时按总纲脱敏：`192.168.10.3` → `*.*.10.3`；`127.0.0.1`、`localhost` 保留完整；其余敏感数据用 `*` 替换。三处强制：SQL 字面量、运行日志、全部格式报告文件。
- 日志额外禁止记录密码、完整身份证号、手机号；所有错误信息中文。

### 与国密切换路径

本期 `0x01` 使用已核实的 SM4-GCM（`sm4.NewCipher` + `cipher.NewGCM`）。总纲「待库支持后切换 SM4-GCM-SIV」的处置：gmsm 库能力现已具备，**但确切 API 签名未核实（U-02）**，因此本期不切换；后续切换须新增算法标签（保留旧标签解密能力以兼容历史密文）、核实 API、做兼容回归，并以新 ADR 立项。绝不凭印象写 `NewGCMSIV` 之类的签名。

### 路径命名分歧（据实记录）

`AGENTS.md` 第 223 行原文密钥路径写作 `项目根目/.dbdlp/key`（「项目根目」为总纲原文笔误，语义为「项目根目录」）。经用户裁定，配置目录与密钥文件命名统一为 `.dbdlp`，密钥文件为 `项目根目录/.dbdlp/key`；总纲原文不回写，本决策与全库文档按裁定口径执行（U-06 已关闭，见 `OPEN-DECISIONS.md`）。

## Consequences

**正面**

- 满足总纲「ENC(base64) 加密存储、加载自动解密、保存自动加密」与 32 字节密钥 / 0600 权限的全部硬要求，填补此前仅「凭据引用」、无加密方案与密钥管理的空白。
- 算法标签路由让 AES 与国密共存、可平滑演进；tag 校验提供完整性保护，密文被篡改会直接报错而非静默产出错误明文。
- 「密钥失败即终止、绝不回退」消除了最危险的一类降级：用内置默认密钥加密凭据，等于没有加密。
- 明文凭据不落库、不进日志/报告/前端，配合第 14 章脱敏策略与审计日志，形成完整的敏感数据保护闭环。
- 支撑本期控制台的数据源增删改查与批量导入：批量导入的凭据同样自动加密，且连接测试门禁保证不落脏数据。

**负面 / 需承担的成本**

- 密钥文件是单点：丢失即无法解密已存凭据，必须由运维纳入备份与权限管控；本期无自动轮换，轮换需停机窗口。
- 每次加解密有 AEAD 开销与 nonce 生成开销，但只发生在数据源配置读写路径，不在每列采样热路径上，影响可忽略。
- 需要严格约定「非 `ENC()` 输入按明文返回」的兼容行为，避免历史/误配字段被静默当作密文处理；已在接口契约中写死。
- 多实例部署若共享同一存储库，必须共享同一密钥文件，部署文档需明确；本期 MVP 为单机部署，暂不构成约束。



**风险与护栏**

- `KeyStore.LoadOrInit` 的任何错误都必须由调用方终止进程；禁止在 catch 中吞掉错误继续启动。
- `Hit` / `Candidate` 中不得出现可落库的明文字段；`Cipher.Decrypt` 结果不得写入任何日志字段。
- 算法标签 `0x00` / `0x01` 之外的取值必须报错终止，为未来 SM4-GCM-SIV 预留新标签但不得提前启用。
- 新增国密实现前必须完成 U-02 的接口存在性核验与旧密文兼容回归测试。
