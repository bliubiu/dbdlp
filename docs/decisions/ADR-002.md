# ADR-002: 多数据源统一抽象与首批落地范围

## Status

Accepted（2026-11-13）

## Background

v1.0 架构文档把产品限定为「达梦数据库敏感数据扫描发现平台」，采集层只有 `internal/collector/dm8/` 一个方言适配，全文档以达梦 DM8 字典视图为前提，与总纲冲突：

- 总纲第 15/16 行要求「统一数据源抽象，优先落地 Oracle 和达梦」「只读连接、连接池、统一数据采集层」。
- 总纲第 27 行要求数据源支持 Excel/YAML 批量导入与增删改查并写入后端存储库。
- 总纲第 61~66 行点名五个原生驱动：`go-ora`、`go-sql-driver/mysql`、`pgx v5`、`chunanyong/dm`、`openGauss-connector-go-pq`。
- 总纲第 233 行要求大结果集流式读取、分页展示与导出，避免内存溢出。

核心问题：如何让新增方言不改动采集／采样／聚合／报告链路；首批实现哪几种方言，避免 MVP 过度扩张。

## Decision

**采用 `database/sql` + 统一 `Driver` 端口 + 方言适配器的形态；首批实现 Oracle 与达梦，MySQL/PostgreSQL 为预留扩展，openGauss 暂缓。**

### 抽象设计

- 领域层 `domain/port/driver.go` 定义 `Driver` 接口：`Dialect()` / `Connect()` / `ListSchemas()` / `ListColumns()` / `TableStats()` / `SampleRows()` / `Placeholder()` / `QuoteIdentifier()`。
- `Connect` 返回 `ReadOnlyConn` 只读句柄（只暴露 `Ping` / `Query` / `Close`），`Query` 返回流式 `Rows`；写方法不在接口内，类型层阻断 DDL/DML。
- 每个数据源实例一个 `*sql.DB` **目标库只读连接池**，参数落 `data_source` 表**每实例字段**（`conn_max_open=2`、`conn_max_idle=1`、`conn_timeout_ms=10000`、`query_timeout_ms=30000`，见 02 文档 10.3 DDL）；`dbdlp.toml` 仅提供默认值，可按实例覆盖。`conn_max_lifetime` 本期「待验证」，不新增配置项。此只读池与后端本地 **SQLite 单写者池**（`storage.max_open_conns=1`，见 8.3）是两个独立概念，不得混用（DIFF-01 裁定）。
- `infrastructure/datasource/readonly.go` 实施 SQL 白名单守卫：只放行 `SELECT` / `WITH` 开头的单条语句，拒绝写关键字、分号多语句与注释绕过，记中文 WARN 日志；与只读账号双保险。
- SQL 差异（字典视图、系统模式排除、占位符、分页、标识符引用）全部收敛到方言适配器；上层零感知具体数据库类型。
- 新增方言只需：实现 `Driver` + 在 `registry.go` 注册 + 补元数据 SQL，上层零改动。

### 首批落地范围

| 方言 | 状态 | 驱动（已核实） |
|---|---|---|
| Oracle | **P0 首批** | `github.com/sijms/go-ora/v2`，驱动名 `oracle`，DSN `oracle://user:pass@host:1521/service` |
| 达梦 | **P0 首批** | `gitee.com/chunanyong/dm`，驱动名 `dm`，DSN `dm://user:pass@host:5236?schema=XXX` |
| MySQL | P1 预留（目录占位，MVP 不实现） | `github.com/go-sql-driver/mysql` |
| PostgreSQL | P1 预留（目录占位，MVP 不实现） | `github.com/jackc/pgx/v5/stdlib` |
| openGauss | **暂缓** | U-01 已关闭（驱动签名已取得）；实现仍按总纲本期不排期 |

### 配套决策

- **连接测试门禁**：`TestConnection` = `Connect` → `Ping` → 方言探针查询，全部成功才允许保存；失败抛中文错误、不落库、不留半条记录。批量导入采用**逐条门禁 + 部分成功**：逐条测试、逐条独立事务、允许部分成功、失败行不入库且逐行中文回显、重复导入幂等去重；不整批回滚（02 文档 7.5／13.2；DIFF-01 裁定）。
- **采样口径**：每列默认抽样 20 行、主键范围分页（`WHERE pk > last_key ORDER BY pk LIMIT n`），禁深偏移 `OFFSET`；无主键表退化为受限扫描并记中文警告；大表按阈值降级或跳过；结果集流式 `Rows.Next()` 逐行处理。
- **元数据落库**：`schema_meta` / `table_meta` / `column_meta` 三表，`scan_checkpoint` 支撑断点续扫，`data_source` 支撑增删改查与批量导入。

选型对比（架构文档 2.1，加权）：每库各写一套采集逻辑 14、统一 `Driver` 端口 25、引入 ORM 18 → 锁定统一端口。ORM 被否决：元数据字典查询、主键分页、只读强制、流式读取都需原生 SQL，ORM 反增约束，且总纲已指定各库原生驱动。

## Consequences

**正面**

- 满足总纲「统一数据源抽象」「统一数据采集层」，方言扩展成本从「复制整条链路」降为「实现一个接口」。
- 只读约束在类型层 + SQL 守卫层 + 账号层三重生效；目标库只读池、流式读取、限流、断点续扫在所有方言一致，默认值由 `dbdlp.toml` 提供、可按 `data_source` 每实例覆盖，与 SQLite 单写者池分开治理（DIFF-01）。
- 首批聚焦 Oracle + 达梦，MVP 范围可控；连接测试门禁在入口挡住脏数据源；MySQL/PG 占位使后续扩展免重构。

**负面 / 成本**

- `Driver` 接口需一次设计到位容纳五方言字典差异（`Placeholder` / `QuoteIdentifier` / 分页）。
- 五种方言元数据 SQL 需各自集成测试库，环境准备成本上升；本期 openGauss 不纳入，客户若以 openGauss 为主需等解除后另行排期（已显式声明，不隐式承诺）。

**已验证结论**

- **U-03 已关闭**：Oracle（e2e-oracle 11.2.0.4）／达梦（e2e-dm8）／openGauss（e2e-gauss 6.0.0）字典视图、系统模式与分页语法均真机验证通过（2026.11.13.3）；未验证视图不得写进生产代码。
- **U-01 已关闭**：openGauss 驱动签名已取得；实现仍按总纲本期暂缓排期。

**达梦已知坑**：开启 `COMM_ENCRYPT_NAME=AES128_ECB` 致连接异常；字段名勿加双引号、建议 UTF-8 不区分大小写。已写入核实结论表供前置规避。

**风险与护栏**

- 只读守卫须覆盖分号多语句与注释绕过；参数一律占位符绑定、标识符经 `QuoteIdentifier`，禁字符串拼接。
- 方言差异表是设计基线非运行时代码；新增适配器前须对照该库当前 tag 的 README 核实导入路径、驱动名、DSN。
- MySQL/PG 预留包本期不得含半成品代码，避免「看起来支持但跑不通」。
