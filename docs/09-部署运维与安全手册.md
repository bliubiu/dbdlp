## 1. 部署形态与拓扑

### 1.1 锁定形态（架构第 18 章）

| 项 | 锁定值 |
|---|---|
| 交付主体 | Go 单二进制（`CGO_ENABLED=0` 交叉编译，纯 Go 依赖） |
| 后端 | 二进制内承载 `interfaces/http`（`/api/v1/*`＋静态资源）与 `interfaces/cli`（`scan`/`report`/`retry`/`serve`/`datasource`/`resume`/`init`） |
| 前端 | Next.js 16.2+ App Router 静态导出 `web/out`，由 Go 进程**同源托管**；运行期无独立 Node 服务 |
| 本地存储 | SQLite WAL，`data/dbdlp.db`；企业部署可切 PostgreSQL |
| 目标库 | 只读账号，首批 Oracle（`1521`）与达梦（`5236`）；MySQL/PG 预留，openGauss 本期暂缓（U-01） |
| 监听 | `[web].listen` 默认 `127.0.0.1:8080`（仅本机）；远程须显式改配置 ＋ TLS ＋ 反向代理 |
| 运行数据 | `data/`（库、导入模板、临时）、报告独立 `项目根/reports/`、日志独立 `项目根/logs/`、密钥 `.dbdlp/`（仅 `key`） |
| 资产数据源 | 写后端 `data_source` 表，控制台/CLI 增删改查与 Excel/YAML 批量导入；不再维护独立本地数据源配置文件 |

### 1.2 拓扑图

```text
  ┌──────────────────────── 内网／信创单节点（无外网出口） ────────────────────────┐
  │   运维/安全合规 ──HTTPS(内网)──> 反向代理(可选,TLS) ──> 127.0.0.1:8080          │
  │                                            ┌───────────▼───────────┐          │
  │                                            │  dbdlp 单进程(单二进制)  │          │
  │                                            │  ├ /api/v1/*  接口       │          │
  │                                            │  ├ web/out    控制台静态 │          │
  │                                            │  └ CLI 子命令(一次性)    │          │
  │                                            └───┬────────┬────────┬───┘          │
  │                       只读 SQL(连接池)        │ 文件   │ 文件   │                 │
  │                       ┌──────────────────────┘        │        │                 │
  │                       ▼                              ▼        ▼                 │
  │              ┌─────────────────┐   ┌──────────────────────────┐  ┌────────┐     │
  │              │ Oracle / 达梦    │   │ data/  dbdlp.db(+wal/shm) │  │ logs/  │     │
  │              │ (只读,首批两种)  │   │ reports/(项目根) .dbdlp/  │  │ 独立   │     │
  │              │ 1521 / 5236     │   │ key(0600) dbdlp.toml     │  └────────┘     │
  │              └─────────────────┘   │ configs/rules             │                 │
  │                                    └──────────────────────────┘                 │
  └──────────────────────────────────────────────────────────────────────────┘
```

进程边界要点：
- **一个二进制、一个常驻监听端口、一个本地存储库文件**。`serve` 常驻；其余 CLI 一次性。
- **SQLite 单写者约束**：`[storage].max_open_conns=1`（必须）。同 `data/dbdlp.db` 不允许多进程并发写入；`serve` 常驻期执行写库 CLI 应错峰或先暂停，观察 `busy_timeout_ms=5000` 锁等待避免 `database is locked`。
- 到目标库连接池是另一套参数（默认 `max_open_conns=2`、`query_timeout=30s`、`connect_timeout=10s`，架构 5.2/ADR-002），与本地 `max_open_conns=1` 非同一处。
- **运行账号专用低权限**（非 root）：仅对 `data/`/`logs/`/`.dbdlp/` 可写；对二进制、`web/out/`、`configs/`、`dbdlp.toml` 只读。

### 1.3 端口与进程边界清单

| 方向 | 端口／对象 | 规则 |
|---|---|---|
| 入站 | `127.0.0.1:8080` | 默认仅本机；远程须显式改 `[web].listen` ＋ TLS ＋ 反向代理 ＋ 防火墙白名单，禁止裸奔内网全段 |
| 出站 | 目标库 `1521`/`5236` | 仅放通已纳入资产清单的具体实例 |
| 出站 | 公网 | **不放通**；离线运行时不访问外网、不拉 CDN、不下载模型/规则/字体 |
| 进程内 | `data/dbdlp.db`、`-wal`、`-shm` | 单实例单写；备份须含 WAL（见 6.1） |
| 文件 | `.dbdlp/key` | 仅运行账号可读；绝不进镜像/版本库/外发 |

### 1.4 内网／信创离线部署约束

- **离线构建**：`CGO_ENABLED=0 go build` 产单二进制；`modernc.org/sqlite`、`go-ora/v2`、`chunanyong/dm`、`gmsm`、`excelize/v2` 均纯 Go，无需目标库客户端动态库。`vendor/` 或离线 module cache 随包，`GOPROXY=off` 验证。
- **规则与配置随包**：`configs/rules.yaml`、`dbdlp.toml` 模板、导入模板随包；运行时不依赖外网。
- **信创架构**：按目标实测设 `GOARCH`，先 `go tool dist list` 确认再填；不臆断 `loong64`/`mips64le`，标「待验证」（责任：运维＋架构师）。达梦 `chunanyong/dm` 纯 Go，无需客户端。
- **前端离线自查**：`web/out/` 须无外部 CDN 引用（脚本/字体/图标/图表全本地化），否则破坏离线约束；标「待验证」，由前端构建门禁加外链扫描。
- **选型与成本**：按 `references/architecture/mvp-stack.md` 与 `references/cost-models/development-costs.md`，本项为内网/信创离线私有化，采用「自托管单二进制（systemd 托管，可选 Docker 封装）」；**不采用** Vercel/CloudBase/Railway 等需外网方案。成本集中在服务器/信创节点、备份介质、日志监控运维、图标字体授权合规（`lucide-react` 为 ISC 许可适合私有化分发）；离线无云服务订阅成本（ADR-003）。

### 1.5 托管方式（平台无关规则）

主推 systemd；Docker 仅可选封装，二选一，不并存。

```ini
# /etc/systemd/system/dbdlp.service（示意，路径按实际安装目录调整）
[Unit]
Description=dbdlp 数据库敏感数据扫描发现平台
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=dbdlp
Group=dbdlp
WorkingDirectory=/opt/dbdlp
ExecStart=/opt/dbdlp/dbdlp serve --config-dir /opt/dbdlp
Restart=on-failure
RestartSec=10s
# 不在此写任何口令或 DSN；凭据一律 ENC 加密落库（data_source 表）
UMask=0077

[Install]
WantedBy=multi-user.target
```

可选 Docker：镜像只含二进制、`web/out/`、`configs/`、`dbdlp.toml` 模板；**`data/`/`logs/`/`.dbdlp/` 必须为持久化卷，密钥绝不打进镜像**；容器内非 root；配置目录参数指向挂载配置卷。本手册只约束「可回滚、健康检查、备份、环境变量、最小权限」平台无关项。

### 2.2 后端离线构建命令

```bash
# 0) 依赖门禁：构建即验证，幻觉 import 在此必红
go version
go build ./... && go vet ./...
go test ./...

# 1) 预置离线依赖（有外网构建机一次，随包分发 vendor/ 与 go.sum）
go mod vendor

# 2) 断网验证：离线条件下构建必须成功
GOPROXY=off GOSUMDB=off GOFLAGS=-mod=vendor go build ./...

# 3) 产出发布二进制（纯 Go、去符号、去路径、注入 CalVer）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  GOFLAGS=-mod=vendor GOPROXY=off GOSUMDB=off \
  go build -trimpath -ldflags "-s -w -X main.version=2026.11.13.0" \
  -o build/dbdlp ./cmd/dbdlp

# 4) 产物自检
file build/dbdlp                    # 期望静态链接 ELF，无动态依赖
sha256sum build/dbdlp > build/checksums.sha256
```

- `GOARCH`/`GOOS` 按目标实测：先 `go tool dist list` 再替换；非 amd64/arm64 标「待验证」。
- 版本注入键 `main.version` 为示意，实际以 `cmd/dbdlp/main.go` 为准，标「待验证」；若实现未暴露该变量改用随包 `VERSION` 文件，二者只用其一。
- 随包：`vendor/`(+`go.sum`)、`configs/rules.yaml`、`dbdlp.toml` 模板、导入模板、文档、CHANGELOG、校验和。

### 2.3 前端构建（Node ≥ 20.9）


### 2.6 版本标注（CalVer）

- 版本号与 CHANGELOG 条目一律 **`YYYY.MM.DD.MICRO`**，示例 `2026.11.13.0`；同日二次发布 MICRO 递增 `.1`，不跳号、不语义化。
- 三处一致：包目录名、`VERSION` 文件、二进制 `-ldflags` 注入值（或 `VERSION` 其一）；CHANGELOG 同号记录变更、影响范围与回滚要点。
- 每次发布生成 `checksums.sha256`；升级前校验新包、回滚前校验旧包，二者留档。错误信息一律中文。

### 2.7 升级步骤（低峰窗口）

```bash
# 0) 判据：无运行中任务；有则先暂停并确认检查点已落库
curl -s -H 'Authorization: Bearer <token>' \
  'http://127.0.0.1:8080/api/v1/tasks?status=running'      # 期望 items 为空

# 1) 记录当前版本与校验和（回滚依据）
cat VERSION
sha256sum dbdlp web/out/* >> /backup/dbdlp/upgrade-<date>.before.sha256

# 2) 全量备份（第 6 章），至少含 data/、.dbdlp/、dbdlp.toml、configs/；校验可读后继续

# 3) 校验新包完整性
sha256sum -c dbdlp-2026.11.13.1-linux-amd64/checksums.sha256

# 4) 停服
sudo systemctl stop dbdlp

# 5) 仅替换「无状态」文件，保留本地运行数据与凭据
cp dbdlp-2026.11.13.1-linux-amd64/dbdlp ./dbdlp
rm -rf web/out && cp -r dbdlp-2026.11.13.1-linux-amd64/web/out web/out
cp dbdlp-2026.11.13.1-linux-amd64/configs/rules.yaml configs/rules.yaml
cp dbdlp-2026.11.13.1-linux-amd64/VERSION VERSION
# 不覆盖：dbdlp.toml、data/、.dbdlp/、logs/
# 若新版 toml 新增字段，人工比对后增量合并，禁止整篇覆盖

# 6) 启动（迁移由 migration.go 按 user_version 增量、事务内，失败回滚带中文错误，架构 10.5）
sudo systemctl start dbdlp

# 7) 冒烟（9.3）；观察 logs/ 当日无 ERROR 新增
```

迁移兼容性：架构 10.5 规定 MVP 阶段**不做破坏性迁移**（不删列、不改字段语义，确需变更时「新增列＋双写＋后续版本清理」），故上一版本二进制通常可读取新版 schema，是可回滚前提。若升级引入破坏性 DDL，则该版本**不具备回滚条件**，须升级前用数据库备份＋停机窗口显式声明，禁止静默升级。

### 2.8 回滚步骤与可回滚判据

**可回滚判据**：

| 判据 | 判定 |
|---|---|
| 上一版本完整包 ＋ `checksums.sha256` ＋ 升级前数据库备份三者齐备 | 具备；缺一即不具备，须先补齐再升级 |
| 升级后 `healthz`/冒烟连续失败、密钥报 2003、迁移失败带伤启动 | 必须立即回滚 |
| 登录、`GET /api/v1/datasources`、`GET /api/v1/config` 出现 5xx 或回显异常 | 必须立即回滚 |
| 报告/日志出现完整明文敏感值、密码非 `"******"` 占位 | 必须立即回滚并按安全事件处置 |
| 新版迁移含破坏性 DDL | 该次升级不具备「仅换二进制」回滚，须走数据库备份恢复 |

```bash
sudo systemctl stop dbdlp
# 还原上一版本无状态文件（留档包，校验和比对）
cp /backup/dbdlp/dbdlp-2026.11.13.0/dbdlp ./dbdlp
rm -rf web/out && cp -r /backup/dbdlp/dbdlp-2026.11.13.0/web/out web/out
cp /backup/dbdlp/dbdlp-2026.11.13.0/configs/rules.yaml configs/rules.yaml
cp /backup/dbdlp/dbdlp-2026.11.13.0/VERSION VERSION
sha256sum -c /backup/dbdlp/dbdlp-2026.11.13.0/checksums.sha256
# 数据库二选一（按 2.7 兼容性）：3a) 无破坏性迁移保留当前库；3b) 需整库回退用升级前备份替换并清理 WAL
#   cp /backup/dbdlp/dbdlp-<date>.db data/dbdlp.db
#   rm -f data/dbdlp.db-wal data/dbdlp.db-shm
sudo systemctl start dbdlp
curl -s -H 'Authorization: Bearer <token>' http://127.0.0.1:8080/api/v1/config
# CHANGELOG 与未决项登记回滚原因、版本、时间、责任人
```

回滚保留策略：**至少保留上一版本完整包 ＋ 校验和 ＋ 对应数据库备份**，至新版本稳定运行一个完整低峰周期后再归档；任何部署都必须可回滚到上一版本。


## 4. 日志运维

### 4.1 强校验基线（与 01／02 文档完全一致）

> **强校验基线（四项，一字不改，原样保留）**：默认日志级别 INFO；日志目录 `项目根目录/logs/`；日志格式串；日志保留 32 天。

| 项 | 锁定取值 | 来源 |
|---|---|---|
| 级别 | `TRACE`/`DEBUG`/`INFO`/`WARN`/`ERROR`（顺序 `TRACE>DEBUG>INFO>WARN>ERROR`），**默认 `INFO`**；`FATAL/PANIC` 内部保留不开放 | PRD 8.3、架构第 9 章 |
| 时间戳 | `YYYY-MM-DD HH:MM:SS.SSS`，**本地时间、不含时区** | PRD 8.3、架构第 9 章 |
| 行格式 | `YYYY-MM-DD HH:MM:SS.SSS  日志级别  trace_id  线程ID或进程ID  模块:行号 - 日志内容` | PRD 8.3、架构第 9 章 |
| 输出通道 | **文件 ＋ 终端双通道**（`[log].console = true`） | PRD 8.3、架构第 9 章 |
| 路径 | **`项目根目录/logs/`**；`[log].dir = "logs"` | PRD 8.3、架构 8.2、第 9 章 |
| 命名 | `dbdlp-YYYYMMDD.log`（`[log].file_prefix = "dbdlp"`） | PRD 8.3、架构第 9 章 |
| 轮转 | **按日轮转，每日一文件；保留 32 天；自动清理过期**（`retention_days = 32`，固定不可改小） | PRD 8.3、架构 8.3、第 9 章 |
| 编码／语言 | UTF-8，日志内容统一中文；错误信息一律中文 | PRD 8.3、架构第 9 章 |
| 脱敏 | **禁止记录密码、完整身份证号、手机号**；任何级别不得打印样本原值 | PRD 8.3、架构第 9 章 |

格式示例（占位示意，不含真实敏感值）：

```text
2026-11-13 22:14:03.127  ERROR  18432  scan/run_task.go:96 - 数据源连接测试失败：主机不可达，请检查地址与端口
2026-11-13 22:14:05.402  WARN   18432  engine/rule_loader.go:41 - 规则 MOBILE_PHONE 未启用，已跳过
```

四项强校验在上线前、日常、升级后检查单（第 9 章）逐项验证。

### 4.2 轮转与 32 天清理验证命令

清理在**每日首个日志事件惰性执行**，删 mtime 超 32 天的 `dbdlp-*.log`；失败记 WARN 不影响主流程。

```bash
date +%Y%m%d
ls -1 logs/dbdlp-*.log | sort
ls -1 logs/dbdlp-*.log | wc -l                          # 正常 <= 32（含当日）
find logs -maxdepth 1 -name 'dbdlp-*.log' -mtime +32 -print   # 期望无输出
touch -d '33 days ago' logs/dbdlp-$(date -d '33 days ago' +%Y%m%d).log   # 跨日轮转演练
./dbdlp datasource add --name SMOKE-01 --dialect oracle --host <host> --test
find logs -maxdepth 1 -name 'dbdlp-*.log' -mtime +32 -print   # 期望无输出
file -bi logs/dbdlp-$(date +%Y%m%d).log                      # 终端同格式 + UTF-8 中文
```

Windows：`Get-ChildItem logs\dbdlp-*.log | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-32) }`（期望无输出）。

### 4.3 格式与编码核查

```bash
head -n 5 logs/dbdlp-$(date +%Y%m%d).log
grep -Ec '^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}\.[0-9]{3}  (DEBUG|INFO|WARN|ERROR)  [0-9]+  [^ ]+:[0-9]+ - .+' \
  logs/dbdlp-$(date +%Y%m%d).log
curl -s -H 'Authorization: Bearer <token>' http://127.0.0.1:8080/api/v1/config   # 级别默认回显（不含密钥/DSN）
```

`模块:行号` 由日志封装 `runtime.Caller` 取调用点，禁止手写；时间戳不带时区后缀。

### 4.4 脱敏核查与禁止项审计口径

```bash
LOG=logs/dbdlp-$(date +%Y%m%d).log
grep -En '1[3-9][0-9]{9}' "$LOG"                       # 完整手机号
grep -En '[0-9]{17}[0-9Xx]' "$LOG"                     # 完整身份证号
grep -En '(password|passwd|pwd|口令|密码)[=: ]+[^ ]' "$LOG"  # 口令明文
grep -En '([0-9]{1,3}\.){3}[0-9]{1,3}' "$LOG"          # 未掩码 IPv4，逐条核对
grep -En '\*\.\*\.[0-9]{1,3}\.[0-9]{1,3}' "$LOG" | head   # 期望 IPv4 形态 *.*.10.3
```

审计口径：① **三处强制脱敏**（架构 14.2）：SQL 字面量、运行日志（全级别）、报告文件。② **IPv4 规则**：`192.168.10.3`→`*.*.10.3`（留后两段）；`127.0.0.1` 与 `localhost` 保留完整。③ **禁止记录项**：密码、完整身份证号、手机号；任何级别不得打印样本原值，DEBUG 仅可打印采样统计与命中摘要。④ **错误一律中文**含原因码，不打印明文口令/连接串/密钥路径/堆栈。⑤ **禁止绕过**：业务代码不得 `fmt.Println` 直写，须经统一 `Logger` 写入前过 `sanitize`。⑥ 审计事件另存 `audit_log` 表（库内长期保留），与「日志 32 天清理」互补，不因轮转丢失审计证据（见 6.4）。

### 4.5 红线

- **日志绝不写回 `data/`**：`logs/` 独立；任何重定向到 `data/` 或当运行数据备份都违反 PRD 8.3 与总纲。
- 不得因「磁盘紧」关闭日志、删当日日志、关 `console` 规避；日志级别不得长期停在低于默认的过细级别 `TRACE`/`DEBUG`（**默认 `INFO`**；五级 `TRACE`/`DEBUG`/`INFO`/`WARN`/`ERROR`）。
- 清理只能由程序 32 天惰性策略执行；手工删除仅限故障处置中「已归档历史文件」，不得删审计证据对应的库内记录。

## 5. 凭据与密钥

### 5.1 `ENC(base64)` 密文形态

存储固定为 `ENC(Base64(载荷))`，载荷字节序（架构 7.1、ADR-003）：

```text
[0]            算法标签 1 字节：0x00 = AES-256-GCM，0x01 = SM4-GCM
[1..12]        nonce 12 字节（每次 crypto/rand 独立生成，同密钥严禁复用）
[13..N-17]     密文（变长，长度 = 明文长度）
[N-16..N-1]    认证 tag 16 字节（AEAD Seal 追加）
最短合法载荷 29 字节；短于此直接判非法密文。
```

| 位置 | 形态 |
|---|---|
| `data_source` 表 | `password_enc`/`host_enc`/`dsn_enc` 只存 `ENC(...)`，无明文字段 |
| `dbdlp.toml` | `postgres_dsn` 仅 `driver=postgres` 时必填，须 `ENC()` 或环境变量引用，绝不写明文 |
| API 响应 | `password` 恒为 `"******"`；`host`/IP 按脱敏处理 |
| 日志／报告 | IP 按 `*.*.10.3`；密码/身份证/手机号禁止出现 |

解密识别 `ENC()` → Base64 解码 → 读第 0 字节按标签选实现（AES 用完整 32 字节／SM4 用前 16 字节）→ `Open` 校验 tag；**未识别标签直接报错终止，不猜测、不回退**；非 `ENC()` 按明文原样返回（兼容非敏感字段）。加载自动解密、保存自动加密，明文仅内存瞬时使用。

### 5.2 密钥首次生成、权限与备份

| 项 | 规定 |
|---|---|
| 生成 | 首次运行（`./dbdlp init --config-dir .`）由 `crypto/rand` 生成 **32 字节**写入 `.dbdlp/key`；禁止手工编辑 |
| 权限 | Unix `0600`（`key_file_mode=384`）；Windows 当前用户独占 ACL |
| 查找顺序 | `--config-dir` 指定目录 ＞ 项目根 `./.dbdlp` ＞ `~/.dbdlp`，命中即止（架构 7.5/ADR-003） |
| 备份 | 密钥是单点，须加密离线备份，与数据备份分离、取用记审计；**绝不进镜像/版本库/工单** |
| 多实例 | MVP 单机单进程；未来多实例共享存储库须共享同一密钥文件（ADR-003） |

初始化后须 `stat -c '%a' .dbdlp/key` 期望 `600`。

### 5.3 密钥轮换（停机人工流程；代码实测无轮换子命令，本期不提供自动轮换）

本期**不提供自动轮换**（架构 7.3、ADR-003）。停机窗口步骤骨架：① 停服、确认无运行中任务；全量备份 `data/` 与 `.dbdlp/key`（旧密钥单独加密留档至新密钥稳定一个低峰周期）。② 旧密钥解密全量 `ENC()` 字段（`data_source` 表），内存形成明文清单，**不落盘、不进日志**。③ 生成新 32 字节密钥写 `.dbdlp/key`（0600）原子替换；新密钥重加密并原子写回。④ 启动并逐条连接测试门禁（5.6），全部通过才算成功；任一失败用旧密钥备份整体回退。⑤ CHANGELOG 与未决项登记留痕。

> **2026-11-14 代码实测**：`internal/interfaces/cli/root.go` 子命令清单为 `init`/`datasource`/`scan`/`report`/`retry`/`resume`/`serve`，**无密钥轮换子命令**；本期按架构 7.3／ADR-003 **不提供自动轮换**。以上①②③④⑤为停机人工流程骨架，具体「解密全量并重加密」动作须由后续实现提供能力后另立 SOP；本手册**不臆造子命令名与参数**。轮换期间禁止新旧密钥并存对外服务。

### 5.4 密钥损坏／丢失处置

硬要求（架构 7.3、ADR-003、错误码 2003）：密钥不存在／权限不足／长度非 32 字节／解码失败 → **直接终止进程**，中文错误「密钥读取失败，进程已终止」；**绝不回退默认密钥、绝不生成临时密钥顶替、绝不降级为明文**。

| 场景 | 处置 |
|---|---|
| 权限被误改（如 `0644`） | 停服 → `chmod 600 .dbdlp/key`（Windows 重设独占 ACL）→ 启动验证；不改动密钥内容 |
| 文件损坏／长度非 32 字节 | 停服 → 从加密离线备份恢复 `.dbdlp/key` → 校正 `0600` → 启动 ＋ 连接测试验证解密 |
| 文件丢失且有备份 | 同上；恢复后逐条连接测试确认历史 `ENC()` 可解 |
| 文件丢失且无备份 | 已存 `ENC()` 凭据**不可解**，不得重建空密钥继续运行；按流程重新录入数据源（重走连接测试门禁），历史密文字段由管理员登记后处置，全程记审计 |
| 绝不做 | 不新建空/全零密钥、不把 `ENC()` 改明文、不塞默认密钥、不吞错误继续启动 |

## 6. 数据与备份

### 6.1 SQLite WAL 备份（正确方法）

**禁止直接 `cp data/dbdlp.db`**：WAL 未 checkpoint 的帧在 `-wal`，只拷主库会丢数据。三选一：

```bash
# 方法 A（推荐，在线一致性备份）：SQLite 在线备份
sqlite3 data/dbdlp.db ".backup '/backup/dbdlp/dbdlp-20261113.db'"

# 方法 B（停机窗口，三件套一致性拷贝）：先 checkpoint 再整体拷贝
sqlite3 data/dbdlp.db "PRAGMA wal_checkpoint(TRUNCATE);"
cp data/dbdlp.db data/dbdlp.db-wal data/dbdlp.db-shm /backup/dbdlp/

# 方法 C（应用内置备份子命令）：2026-11-14 代码实测 CLI 子命令清单无备份子命令，
#         本期该方法不成立，仅作留痕；实际以方法 A 或方法 B 为准，不臆造子命令名
```

> `sqlite3` CLI 是否随内网/信创提供标「待验证」：若无，**只能**用方法 B 停机手工等价（先 `PRAGMA wal_checkpoint(TRUNCATE)`，再三件套拷贝），恢复演练验证完整性；不臆造 `sqlite3` 之外的备份工具接口，也不引用不存在的应用内置备份子命令。

备份触发：每日低峰（建议 `03:00`，落 `22:00-06:00`）执行；前确认无运行中任务或先暂停并确认 `scan_checkpoint` 落库。对象含 `data/` 整目录（库、报告、导入模板）＋ `.dbdlp/` ＋ `dbdlp.toml` ＋ `configs/`。介质加密、离线、与生产分离；取用与恢复均记审计。日志保留 32 天是日志策略，**不等于数据库备份保留期**。

### 6.2 恢复步骤与完整性校验

```bash
sudo systemctl stop dbdlp
cp -a data /backup/dbdlp/data-before-restore-<date>   # 先备份当前库便于二次回退
cp /backup/dbdlp/dbdlp-20261113.db data/dbdlp.db       # 用备份库替换
rm -f data/dbdlp.db-wal data/dbdlp.db-shm              # 清理残留 WAL 伴生文件
sqlite3 data/dbdlp.db "PRAGMA integrity_check;"        # 期望 ok
sqlite3 data/dbdlp.db "PRAGMA journal_mode;"           # 期望 wal
sqlite3 data/dbdlp.db "PRAGMA foreign_keys;"           # 期望 1
sudo systemctl start dbdlp                            # 启动并冒烟：登录→数据源→任务→报告下载
```

恢复后须核对 `audit_log`、任务台账、报告产物（`report_artifact`）与备份时间点一致；历史任务与台账不因恢复被改写（PRD 8.1「可追溯」）。

### 6.6 PostgreSQL 切换注意事项（企业部署）

切换条件：`storage.driver = postgres`，`postgres_dsn` 为 `ENC()` 或环境变量引用；仅替换 `Store` 适配器，业务层零改动（架构 10.1）。切换前全量备份 SQLite 库并制定回滚预案。

架构 10.4 的 DDL 差异（**时间字段推荐保持 `TEXT` 以免时区语义漂移**）：

| SQLite | PostgreSQL |
|---|---|
| `TEXT PRIMARY KEY` | `TEXT PRIMARY KEY`（UUID 字符串一致） |
| `INTEGER`（布尔） | `BOOLEAN`，`0/1` 改 `false/true` |
| `TEXT`（时间） | 推荐保持 `TEXT` |
| `TEXT`（JSON） | `JSONB` |
| `REAL` | `DOUBLE PRECISION` |
| `PRAGMA journal_mode=WAL` | 不适用（PG MVCC），备份改 `pg_dump` |
| `SetMaxOpenConns(1)` | 按 `storage.max_open_conns` 设连接池 |
| 占位符 `?` | pgx 用 `$1`，仓储层 SQL 须经 `Driver.Placeholder` 或 PG 专用实现 |

迁移按 `migration.go` 的 `user_version` 有序增量、事务内失败回滚（架构 10.5）。PG 备份改 `pg_dump`＋cron 每日保留 7 天，恢复 `psql < backup.sql`；切换后重跑第 9 章中与存储相关的全部上线前检查项。

| 监控对象 | 端点／表 | 关注点 |
|---|---|---|
| 任务状态 | `GET /api/v1/tasks?status=`、`GET /api/v1/tasks/{id}`（含 `summary`） | `running`/`paused`/`partial_failed`/`failed`；窗口外任务应暂停且无查询 |
| 进度 | `GET /api/v1/tasks/{id}/progress` | `doneTables/totalTables`、`doneColumns/totalColumns`、`failedCount` 增长与停滞 |
| 失败对象 | `scan_task.summary` 失败/跳过清单 | 单表超时、无主键表、大表降级、二进制跳过原因与中文描述 |
| 检查点 | `scan_checkpoint`（按 `(task_id, table_meta_id, column_name)` 唯一） | `last_key` 是否推进；`resume` 是否从最近主键继续 |
| 审计 | `GET /api/v1/audit-logs?actor=&action=` | 权限拒绝、连接测试失败、报告导出、配置变更 |
| 规则快照 | `GET /api/v1/rules/snapshots` | 任务是否带 `rule_version`，历史报告可复现 |

失败处置遵循「单表/单字段失败不阻断整体任务」（PRD 8.1）；`failedCount` 持续增长或检查点长时间不推进即触发 7.5 告警。

### 7.3 资源占用与低峰窗口

巡检：CPU/内存/磁盘（`data/` WAL 是否膨胀、`logs/` 文件数是否 ≤ 32）；低峰窗口 `[scan].low_peak_window = "22:00-06:00"`，窗口外任务暂停且不向业务库发查询；连接池到目标库每实例上限 2、单查询超时 30s，本地 SQLite 单写者 `max_open_conns=1`；大表 `large_table_rows = 10000000` 超阈值降级/跳过，CLOB 截断 `max_text_len = 2000`，BLOB 跳过；报告导出走流式（excelize `StreamWriter`）+ 分页查询避免内存溢出（架构 12.4）。

```bash
df -h /opt/dbdlp
du -sh data/* reports/* logs/* | sort -h
ls -1 logs/dbdlp-*.log | wc -l                # 期望 <= 32
```

### 7.4 限速并发参数巡检

通过只读端点 `GET /api/v1/config` 回显生效值（`logLevel`、`sampleRows`、`storageDriver`、`cryptoAlgorithm`、`retentionDays`；**不含密钥与 DSN**），对照 `dbdlp.toml` 核对是否被误调高：

| 参数 | 默认 | 合法范围 | 误调风险 |
|---|---|---|---|
| `sample_rows` | 20 | 1～1000 | 调高增加目标库采样压力 |
| `batch_size` | 20 | 1～500（≤ sample_rows 取小） | 过大增加单次查询负载 |
| `concurrency` | 1 | 1～4 | 调高可能压垮业务库 |
| `batch_interval_ms` | 50 | 0～2000 | 调 0 取消节流 |
| `query_timeout_ms` | 30000 | — | 过大拖住目标库 |
| `task_timeout_min` | 120 | — | 超限标记部分失败 |
| `low_peak_window` | `22:00-06:00` | 时间段 | 清空等于不限窗口 |
| `retry_max` | 3 | — | 过大放大重试风暴 |
| `storage.max_open_conns` | 1（SQLite） | 必须为 1 | 改大触发 `database is locked` |
| `log.level` | INFO（默认） | 五值枚举 TRACE/DEBUG/INFO/WARN/ERROR | 长期停 TRACE/DEBUG 致日志暴涨 |
| `log.retention_days` | 32 | 固定 32 | 不允许改小 |

控制台「配置查看」页须展示每个参数生效值与来源层级（命令行/配置文件/默认值）；发现不符先查命令行覆盖，再查 `dbdlp.toml`，最后查默认值，不直接改库。

### 7.5 告警阈值建议（本地告警，不外发、不接外部分析服务）

| 指标 | 阈值 | 动作 |
|---|---|---|
| API 5xx 比例 | > 5%（5 分钟窗口） | 本地通知，核对日志 ERROR |
| 接口 p95 | > 500ms（列表/详情）、首屏 > 3s | 本地通知，排查慢查询与连接池 |
| 任务 `failedCount` | 持续增长或检查点 10 分钟不推进 | 本地通知，按 8.5 处置 |
| 磁盘使用率 | > 85% | 本地通知，按 8.5「磁盘满」处置 |
| 日志文件数 | > 32 或单日异常增大 | 本地通知，按 8.5「日志暴涨」处置 |
| 未处理 ERROR | > 10 次/小时 | 本地通知；出现完整明文敏感值按安全事件处置 |
| 密钥类错误（2003） | 出现即告警 | 立即停服排查，按 5.4 处置 |
| 备份失败／恢复演练失败 | 出现即告警 | 立即补做并复核 |

全部本地留痕，不外发；不接入外部分析、不采集隐私、不上报 IP、不存原始输入（PRD 8.5）。

## 8. 安全与审计

### 8.1 报告导出权限与操作审计

- 明细导出需**单独授权**并记审计；未授权导出拒绝（错误码 1003）且**无文件产出**，审计含操作者/时间/对象/结果（PRD E16、A14）。
- `POST /api/v1/reports` 生成报告写 `report_artifact` 与审计；`GET /api/v1/reports/{id}/download` 下载记审计（架构 13.2）。
- 报告一律只放掩码样例；全格式检索完整明文手机号/身份证/银行卡命中数必须为 0（PRD F11、架构 A12）。
- 审计覆盖：数据源增删改、批量导入、任务启停、复核结论、报告导出、配置变更、权限拒绝（PRD 7.14、架构 15 章）。

### 8.2 控制台会话

- 本期认证按总监裁定：**单管理员 ＋ 会话**，不做 SSO/LDAP（U-08）；如需统一身份源另立需求。
- **首次引导管理员（代码实测）**：`cmd/dbdlp/assembly.go` 的 `bootstrapAdmin` 读取环境变量 `DBDLP_ADMIN_USER`/`DBDLP_ADMIN_PASSWORD`，账号不存在时以 bcrypt 散列建 `web_user`，已存在则不覆盖口令；口令仅从环境变量读取，不落 `dbdlp.toml`、不进日志（README「快速开始」给出示例）。首次部署由运维在受控渠道一次性注入，**口令绝不写进 systemd unit、Dockerfile、命令行历史、工单或日志**（1.5 unit 第 126 行约束）；引导成功后撤销该环境变量。
- 除 `POST /api/v1/auth/login` 外全部端点需 `Authorization: Bearer <token>`；`web_session` 只存 **token 哈希**、设 `expires_at`（`session_ttl_min = 480`）、登出即删（架构 13.1、15 章）。
- 密码用 Argon2id/bcrypt 哈希；连续登录失败按次数递增锁定并记审计（架构 15 章）。
- 默认仅监听 `127.0.0.1:8080`；远程须显式 `[web].listen` ＋ TLS ＋ 反向代理 ＋ 防火墙白名单。
- 前端永不接触明文凭据：数据源响应 `password` 恒为 `"******"`，`host`/IP 脱敏；不缓存、不回显口令（架构 19.1、13.1）。

### 8.3 敏感信息不进日志与报告

三处强制脱敏（SQL 字面量、运行日志、全部格式报告）＋ 禁止项（密码、完整身份证号、手机号）详见 4.4。补充：原始值仅内存瞬时使用，处理完即释放；对外不回显堆栈/连接串/密钥路径内容，错误一律中文（架构 15 章）；报告/界面/日志/接口/导出中完整明文敏感值命中数为 0（PRD 10.3）；IPv4 脱敏 `*.*.10.3`，`127.0.0.1` 与 `localhost` 保留完整。

### 8.5 故障处置表

每类「现象 → 定位 → 处置 → 绝不做 → 防复发」，错误以中文为准，处置记审计。

#### 8.5.1 连接失败／连接测试未通过

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8080/api/v1/datasources/{id}/test
grep 'ERROR' logs/dbdlp-$(date +%Y%m%d).log | tail -n 30      # 查当日 ERROR（不回显口令）
```

- 现象：凭据错误/网络不可达/权限不足/查询超时/规则语法错误/密钥缺失（PRD 8.6），错误码 2001/5000。
- 处置：区分原因逐项修（口令走 PATCH＋重测；网络找 DBA 放通 1521/5236；权限按 5.5 复核）；达梦先排 `COMM_ENCRYPT_NAME=AES128_ECB` 已知坑；失败实例标记失败，**不保存配置**、不影响其他实例。
- 绝不做：不回显口令明文、不跳过连接测试门禁、不写半条记录、不打印连接串。
- 防复发：连接测试门禁 ＋ 目标库审计双重确认；导入记录默认「未验证」。

#### 8.5.2 磁盘满

```bash
df -h /opt/dbdlp
du -sh data/* logs/* | sort -h
ls -1 data/dbdlp.db*                 # 关注 -wal 是否持续膨胀
```

- 处置：暂停任务并确认检查点落库 → SQLite checkpoint（6.1 方法 B）→ 历史报告按归档移入加密介质（**不删 `audit_log`、不删历史任务/台账**）→ 确认 `logs/` 仅留 32 天且 ≤ 32 文件 → 扩容或清 `data/tmp/` → 恢复任务。
- 绝不做：不删 `dbdlp.db`/`-wal`/`-shm` 活动文件、不删 `.dbdlp/key`、不删当日日志、不关日志、不把日志重定向到 `data/`。
- 防复发：磁盘 > 85% 告警（7.5）＋ 每日备份 7 天 ＋ 报告归档 ＋ WAL checkpoint 巡检。

#### 8.5.3 日志暴涨

```bash
grep -Ec '^' logs/dbdlp-$(date +%Y%m%d).log        # 当日行数
ls -1 logs/dbdlp-*.log | wc -l                     # 是否 > 32
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/v1/config   # 核对 logLevel
```

- 定位：是否误调至低于默认的 `TRACE`/`DEBUG`（**默认 `INFO`**）；是否循环错误刷屏；是否绕过 `Logger` 直写；32 天清理是否失效。
- 处置：查生效值来源层级（命令行 ＞ toml ＞ 默认）→ 恢复 `INFO` → 定位刷屏根因 → 确认过期清理生效（4.2）。
- 绝不做：不关日志、不写回 `data/`、不手工 `rm` 当日文件、不长期停 `TRACE`/`DEBUG`。
- 防复发：`log.level` 变更纳入配置变更审计；`logs/` 文件数与单文件大小纳入 7.5 告警。

#### 8.5.4 密钥损坏／丢失

- 现象：启动即终止，中文错误「密钥读取失败，进程已终止」，错误码 2003；`stat -c '%a' .dbdlp/key` 非 600 或长度非 32 字节。
- 处置：停服 → 权限问题则 `chmod 600`（Windows 重设独占 ACL）→ 损坏/丢失从加密离线备份恢复 `.dbdlp/key` → 校正权限 → 启动 ＋ 逐条连接测试验证历史 `ENC()` 可解 → 无备份按 5.4 重新录入并登记。
- 绝不做：**绝不回退默认密钥、绝不生成临时密钥顶替、绝不降级为明文**、不手工编辑密钥内容、不吞错误继续启动。
- 防复发：密钥纳入每日加密离线备份（3.3）＋ 月度恢复演练（6.5）＋ 权限变更纳入巡检（9.2）。

#### 8.5.5 任务中断续扫

```bash
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/v1/tasks/{id}
./dbdlp resume --task <task_id>     # 从 scan_checkpoint 的 last_key 续扫，跳过 done
./dbdlp retry --task <task_id>      # 重试失败对象
```

- 处置：确认状态机（待执行/运行中/暂停/成功/部分失败/失败）→ `resume` 续扫、`retry` 重试、`pause` 暂停落检查点 → 核对已完成字段不重复产出台账，报告可复现（PRD F10、A09）。
- 绝不做：不删库重跑、不手工改 `last_key`、不在同数据源重复发起任务（冲突 3001）、不在 `serve` 常驻写库期间并发起第二个写库进程（1.2 单写者约束）。
- 防复发：检查点推进纳入 7.2 监控；低峰窗口外暂停写检查点；任务参数与规则版本随任务留痕。
