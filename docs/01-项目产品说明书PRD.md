## 1. 背景与问题

### 1.1 现状与痛点
企业业务库分散多种数据库，散存身份证号、手机号、银行卡号、邮箱、地址、统一社会信用代码等。GB/T 43697-2024 于 2024-10-01 实施，确立核心／重要／一般／公开四级框架 [S14]，但不解决「如何定位字段、如何判定、如何生成可审计报告」。

| 痛点 | 具体表现 | 后果 |
|---|---|---|
| 底数不清 | 人工字典＋手动查询，旧系统、备库、同步库无人盘点 | 合规临时应对，事件后被动回溯 [S14] |
| 字段名可伪装 | 敏感列命名 `col_01`，仅字段名无法发现 | 漏扫 |
| 误报高 | 16 位订单号、代码注释数字串误命中银行卡 [S9] | 告警疲劳，真实风险被延误 [S8][S18] |
| 扫描冲击生产 | 全表 `SELECT`、深偏移分页、无并发约束 | 打满 IO、锁表，数百毫秒级延迟 [S8][S9] |
| 结果不可解释 | 缺命中样本数／命中率／校验结论／规则版本 | 无法复核，不能作审计证据 |
| 多源运维重 | 每库一套脚本，实例清单散落文件 | 主库脱敏、备库明文遗漏，变更无留痕 |
| 报告即泄露面 | 明细报告打印完整明文 | 盘点行为制造新泄露风险 |

### 1.2 真实问题陈述
用户要「扫描工具」，真正解决三件事：**不影响生产前提下拿可审计、可复核、可持续维护的敏感资产底数**；**误报可控下把发现转化为风险优先级**；**多数据库、内网信创、无外网环境里让能力长期自运行**。产品方向不是「更强算法」，而是闭环：统一纳管 → 只读低侵入采样 → 可解释识别与校验 → 置信度与风险分级 → 落库台账与复核 → 仅掩码样例报告 → 全程留痕。

### 1.3 现有做法为什么不行
纯人工不可行、无一致性 [S14]；商业云平台绑生态、私有化受限 [S1][S6][S7]；企业套件部署重、需专职、许可复杂、界面旧 [S5][S6]；开源组件只覆盖识别或脱敏单点，不直连库、不遍历元数据、不采样限速、不产出台账报告 [S10][S12][S13][S16]；旧 v1.0 绑达梦单库、依赖内嵌 SDK、采样过大、无控制台与落库，与总纲脱节。

## 2. 竞品分析与差异化
调研联网检索 2026-11-13（来源见 14.3）。**直接竞品**：阿里云 DSC（云原生、绑生态、规模化贵）、IBM Guardium（监控深、部署重贵）、Microsoft Purview（生态深、跨生态弱、不做运行时监控）、Imperva（库层拦截强、非结构化弱）、鸿萌 DataClassifier（信创离线内嵌控制台形态最接近，但闭源不可自维护且功能过载）。**替代开源**：godlp（仅文本识别脱敏 SDK，无连接／采样／台账）、openDLP（字段级分类但仅文件输入、Python 依赖重）、DBMasker（访问脱敏 SDK，写库冲突）、dbmask（发现-脱敏-验证，写库冲突），均只覆盖单点。

**差评共性（对应本项目约束）**：① 误报漏报（纯正则不做校验 [S8][S9][S17]）；② 扫描冲击生产 [S8][S9]；③ 生态锁定部署重 [S5][S6][S7]；④ 覆盖不全漏备库同步库 [S8][S14]；⑤ 结果不可运营、开源停滞 [S12][S16][S17]。

**市场空白**：同时满足「多库（含国产）统一抽象＋内网信创离线单二进制＋只读低侵入（20 行／主键分页／限速／低峰）＋规则可解释可自定义带校验降误报＋资产落库批量导入＋内嵌控制台＋报告仅掩码样例＋全程留痕」的轻量产品极少。

**差异化（做成一等公民）**：**可解释**——每条命中带规则标识／样本数／样本总量／命中率／校验结论／置信度／规则版本；校验器压低「16 位数字即银行卡」误报；人工复核与机器结论分开留存。**低侵入**——只读账号、连接测试门禁、每列 20 行、主键分页、分批限速、低峰窗口、大表降级、单表失败不中断；报告显式标注样本量与「未覆盖」提示。**可自维护**——统一抽象优先 Oracle 与达梦；`dbdlp.toml` 单一入口；资产落库＋批量导入；本期带控制台；四层 DDD＋整洁架构＋TDD；五级日志（TRACE／DEBUG／INFO／WARN／ERROR，默认 INFO）按日轮转保留 32 天。一句定位：**面向内网信创、只读低侵入、规则可解释、可自维护的多数据库敏感资产盘点工具。**

## 3. 产品目标与非目标

### 3.1 产品目标
| 编号 | 目标 | 达成判据 |
|---|---|---|
| G1 | 多源统一盘点 | 同一流程纳管五种库，优先 Oracle 与达梦；新增方言不改采样／识别／分级／报告链路 |
| G2 | 字段级发现 | 16 类内置全量纳入，另支持企业自定义扩展 |
| G3 | 低侵入只读 | 全程只读；每列 20 行、主键分页、分批限速、低峰；无锁表与全表扫描 |
| G4 | 可解释可复核 | 台账含命中数／样本数／命中率／校验结论／置信度／风险等级／规则版本；人工复核与机器结论分开 |
| G5 | 资产可运营 | 资产落库，增删改查＋excel/yaml 批量导入；连接测试通过才允许保存 |
| G6 | 报告不泄露 | Excel／HTML／JSON 三形态只含掩码样例；日志与任务记录无完整明文 |
| G7 | 可私有化可追溯 | 内网离线单二进制；五级日志按日轮转保留 32 天；配置／任务／复核／导出全程留痕 |

### 3.2 非目标（带原因）
| 不做项 | 原因 |
|---|---|
| 实时流量拦截／网关代理／数据库防火墙 | 定位离线周期盘点，不进业务链路，破坏只读低侵入 [S5] |
| 在线／静态脱敏改写与清理 | 会执行 `UPDATE`，与只读冲突；格式保持替换可能改语义 [S16] |
| 权限管控／访问审批／单点登录 | 不替代 DBA 权限；**本期已落地单管理员＋会话鉴权**（`web_user`／`web_session`、token 哈希），不做 SSO／LDAP／多角色与权限矩阵界面；身份源与部署边界**待裁定**，见 12.2.2（登记册 U-08） |
| BLOB／文件 OCR | 二进制默认跳过记原因；OCR 需模型，与离线单二进制冲突 [S14] |
| 自动发现主备／同步／数仓血缘／备份集扫描 | 需更高权限超只读边界；**覆盖边界与首批资产台账待用户裁定**（12.2.2），裁定前本期不实施自动发现与备份集扫描，本 PRD 不把「手动纳入备库同步库」写成结论 |
| 业务数据修改／DDL／任何写操作 | 只读基线；评审须确认采集链路无写操作 |
| 语义模型／NER 引擎 | 本期以自研规则层覆盖，不引入需外网模型 |
| 自适应采样 | 总纲明确「后续增强」；本期固定每列 20 行并标注样本量与未覆盖提示 |
| 数据出境评估／DSAR／ROPA／API 安全等治理扩展 | 超「盘点」范围，属商业治理平台过载部分 [S14] |

## 5. 术语
| 术语 | 定义 |
|---|---|
| 实例（Instance） | 被纳管的数据源连接，含库类型／地址／端口／只读账号／凭据引用／扫描范围与限速 |
| 模式（Schema） | 不同方言的 Schema／用户／Database 统一抽象为「模式」 |
| 资产数据源 | 落后端存储库、可增删改查的实例配置记录（配置对象而非文件） |
| 候选字段 | 经字段名／注释初筛或内容待识别的字段 |
| 样本（Sample） | 字段按主键分页抽取的若干值，默认每列 20 行 |
| 命中率 | 命中某敏感类型的样本数 ÷ 该字段扫描样本总数 |
| 字节扫描器 | 自研组件，对字段原始字节流分段与规范化预处理并提取候选片段，不依赖第三方 SDK |
| Detect／Filter／Verify | 自研管道三段：正则初筛（高召回）、边界噪声过滤、业务校验（校验位／Luhn／号段／字符集）；思想参考 godlp，实现自研 [S11] |
| 校验规则（Verify） | 对正则命中做业务合法性校验，降误报主要手段 |
| 自定义规则 | 企业定义的敏感类型规则（内部证件号／工号／合同号／客户编号等） |
| 置信度 | 由规则强度／是否过校验／列名注释吻合度／命中率综合：高／中／低 |
| 风险等级 | 由敏感类型／存储形态／校验结论／命中率映射：高／中／低／待复核，映射表可配置 |
| 存储形态 | 明文／透明加密／哈希／掩码，用于风险降级判断 |
| 掩码样例 | 报告／台账／界面展示的脱敏值，禁止完整明文 |
| 规则版本 | 任务启动时生效规则集合标识，随任务与报告留痕，保证历史可复现 |
| ENC(base64) | 凭据密文表达形式；明文口令不落盘、不回显、不进日志 |
| 低峰窗口 | DBA 指定允许扫描时段，窗口外任务自动暂停 |

## 6. 全量敏感类型清单

### 6.3 识别机制与校验机制
自研管道（不内嵌第三方 SDK）：
```
字段字节流 → 字节扫描器（分段／编码规范化／候选片段提取）
          → 正则 Detect（高召回初筛）
          → 边界与噪声 Filter（中文上下文、数字粘连、前后缀、占位文本）
          → 校验 Verify（校验位／Luhn／号段／字符集／行政区划）
          → 自定义规则（内置未命中按启用顺序匹配）
          → 命中结果（规则标识、敏感类型、是否过校验、掩码样例）
```
参考 godlp 的 `Detect→Filter→Verify` 与 `conf.yml` 组织思想 [S11]，仅借鉴管道划分，不调用其 API；openDLP 字段级「候选类型＋阈值投票」用于列级聚合参考 [S12]，不引入其 Python 运行时。**校验规则清单（本期必实现，每条须有正负样本单测，见 10.2）**：身份证校验位与出生日期、银行卡 Luhn、手机号段、统一社会信用代码校验位、邮箱格式、IPv4 范围、IPv6 分组、MAC 分组、车牌字符集、邮编格式、固话区号。

### 6.4 置信度与风险分级（可配置）
**置信度**：高＝过校验 且 列名／注释吻合 且 命中率≥阈值；中＝过校验但列名无吻合，或未过校验但格式强且命中率不低；低＝仅正则命中、未过校验、命中率低。语义类最高「中」计，必须进人工复核。

**风险等级映射（默认策略，可配不硬编码）**：
| 条件 | 风险等级 |
|---|---|
| 明文＋高敏感类型（身份证／手机号／银行卡／护照／统一社会信用代码） | 高 |
| 无盐哈希特征（定长十六进制无明文格式） | 中高 |
| 明文＋语义类（人名／地址／公司名） | 中 |
| 透明加密列／加盐哈希 | 中低 |
| 已掩码／已脱敏 | 低 |
| 仅格式命中、校验未通过 | 待复核（进误报样本池） |

默认策略为「明文高敏感＝高、已掩码＝低、仅格式命中＝待复核」，配置化不硬编码，本期已落地；不再引用登记册条目编号作一致性断言（登记册计数与状态见 12.2.1）。是否对接企业内部分类分级标准属**待裁定**，见 12.2.2，本 PRD 不自行结论。

## 7. 功能需求
优先级：P0＝本期必交付必验收；P1＝应交付，缺失需总监书面确认；P2＝后续迭代。完整 EARS 见第 9 章，验收用例见第 10 章。

### 7.1 F1 统一数据源抽象（P0）
定义统一抽象屏蔽方言差异，支持五种库（优先 Oracle 与达梦）；上层采样／识别／分级／报告不感知类型。覆盖连接只读校验、模式清单、表列元数据、表统计、分页采样、类型映射、错误归一化；达梦 DM8 与 Oracle 字典视图／加密列字典／分页语法差异集中方言适配层。验收：同任务分别指向 Oracle 与达梦，台账字段名／类型／命中数／风险等级结构一致；新增第三方言时采样／识别／报告代码无需改动（契约由架构评审确认）。

### 7.2 F2 只读连接与连接池（P0）
仅用只读账号；连接池上限／连接超时／查询超时可配；建立时校验只读属性。**保存前必须执行只读连接测试且通过**，不通过不得保存、不得进扫描，测试过程与结果写审计。凭据以 ENC(base64) 加密存储（见 7.15），接口不回显。验收：凭据错误或权限不足时保存不可用、返具体原因（不回显口令）、审计新增失败事件；只读账号保存后扫描全链路仅只读查询，评审与审计确认无 `UPDATE`／`DELETE`／`DDL`。

### 7.3 F3 元数据读取（P0）
读取模式／表／字段／类型长度／注释／估算行数／主键／加密列标记／表规模标记（含达梦 HUGE 表）；排除系统模式／表／字典表。字段名／注释初筛只减采样不作最终结论，伪装字段仍进内容识别。验收：含 `col_01` 伪装列且存身份证号的表，该列仍标「内容待识别」并进入采样；系统模式不出现在扫描范围。

### 7.4 F4 表与列扫描调度（P0）
按「实例→模式→表→列」拆分任务单元，支持纳入／排除清单、状态流转（待执行／运行中／暂停／成功／部分失败／失败）、断点续扫、失败对象单独重试、单表或单字段失败不中断整体。验收：含 10 张表且 1 张报错的任务，状态「部分失败」、其余 9 张产出台账、失败表记原因且可单独重试成功。

### 7.5 F5 分页限流分批限速低峰执行（P0）
主键范围分页（记录每批最大主键为下批起点），禁深偏移 `OFFSET`；批次大小／间隔／并发度／单查询超时／总时长可配，默认低并发；支持低峰窗口，窗口外暂停、窗口内恢复；无主键表退化为受限行数扫描并记警告；CLOB／TEXT 截断、JSON 提取叶子、BLOB 默认跳过记「未扫描-二进制」。验收：配低峰窗口与并发的任务窗口外无查询、窗口内按配执行；单批超时有限重试后跳过并继续后续。

### 7.6 F6 默认每列 20 行抽样（P0）
**每列抽样默认 20 行**主键分页取得；可在 `dbdlp.toml` 或命令行覆盖但必须记录到任务参数与报告。禁 v1.0 的 100～1000 行分档。大表按阈值降级跳过并记依据。自适应采样为后续增强。报告显式标样本量与命中率，对覆盖不足给「未覆盖」提示与高风险字段追加扫描入口。验收：未配采样时 `sample_total ≤ 20` 且参数记 `sample_rows = 20`；显式配 50 时参数与报告均记 50；高风险字段需复核时控制台提供追加入口且追加不覆盖原结论。

### 7.7 F7 敏感识别引擎与校验机制（P0）
按 6.3 实现自研管道，覆盖 6.1 全量 16 类与 6.2 扩展；每条规则可启停、可配阈值；规则版本随任务留痕；识别在客户端完成，不在库内执行正则。原始值仅内存瞬时使用，不落库／不进日志／不进报告。验收：正负样本集（真实值／订单号／随机串／16 位代码注释／掩码值／普通中文）中过校验正样本正确命中，纯格式命中且校验失败进「待复核」非「高」；禁用某规则时该规则不参与识别且快照仍留定义标记未启用。

### 7.8 F8 置信度与风险分级（P0）
按 6.4 聚合字段级命中数／样本总数／命中率／校验通过／存储形态，算置信度与风险等级；映射表配置化不硬编码；同字段多类型分别记录取最高风险；存储形态判定依据加密列字典与值特征。验收：明文身份证列与已掩码手机号列分别高／低风险且均记存储形态与置信度；仅格式命中未过校验为「待复核」进误报池；改分级映射重跑按新映射、历史任务结果不变。

### 7.9 F9 资产数据源批量导入与增删改查落库（P0）
资产数据源**写入后端存储库**（非文件），提供增查改删启停；支持 **excel 与 yaml 批量导入**，导入前供模板下载与字段校验，结果逐行反馈、重复项按实例标识去重；删除需二次确认且被引用数据源须保留可追溯记录；每次变更写审计。批量导入不跳连接测试门禁：导入记录为「未验证」状态，测试通过才参与扫描。验收：含 20 条（2 条错）的 excel，18 条入库且「未验证」、2 条逐行给原因不入库；未验证数据源发起扫描被拒并提示先测试；删有历史任务的数据源需二次确认、历史可查、审计新增删除事件。

### 7.10 F10 任务调度（P0）
手动与定时触发；任务状态机、断点续扫、失败重试、跳过记录、扫描留痕；记录含任务标识／实例／范围／起止时间／触发方式与操作者／状态／耗时／失败跳过清单／规则版本／采样参数／低峰窗口。验收：运行中任务被中断恢复时从最近批次主键续扫且不重复已完成字段；任一已完成任务可查完整参数与规则版本足以复现。

### 7.11 F11 Excel／HTML／JSON 报告且只放掩码样例（P0）
三格式本期全纳入无取舍。报告须含：**实例、模式、表、字段、样本、命中数、风险等级**，及敏感类型／命中率／置信度／存储形态／规则版本／任务信息／样本量与「未覆盖」提示／跳过失败说明。**所有样例一律掩码，禁完整明文**；明细导出需权限控制与审计（见 4.3）。Excel 六工作表：概览／台账／命中明细／误报复核／规则清单／任务记录；JSON 结构与台账一致供下游；HTML：概况→风险汇总（等级／类型／模式）→高／中／待复核清单→加密脱敏现状→整改建议→附录。验收：已完成任务导出三格式均含七项且字段一致；全文完整明文模式检索命中 0；未授权用户明细导出不可用且尝试记审计。

### 7.12 F12 网页控制台（P0，本期纳入）
按总纲锁定前端技术栈，至少提供：资产数据源管理（列表／增删改查／连接测试／批量导入／模板下载）、扫描任务（创建／配置／启停／重试／进度）、结果台账（筛选／排序／分页／按风险与类型过滤）、人工复核（确认敏感／误报／待确认）、报告中心（三格式导出与留痕）、规则管理（列表／启停／阈值查看）、配置查看（`dbdlp.toml` 生效值与来源）、日志与审计视图。遵循 0.3：统一矢量图标库、克制数据密集型风格、无空洞占位；「左侧导航＋顶部面包屑＋右侧内容区」后台布局，表格支持筛选／排序／分页／批量、删除二次确认、操作可撤销、空状态给具体引导。验收：不使用命令行的安全合规专员仅用控制台完成「新增→测试→建任务→看台账→复核→导出」全流程无需手编配置；任一空列表显具体下一步；全站无 emoji 功能图标、无紫粉渐变。**本期落地事实**：静态导出至 `web/out` 由 Go 同源托管、无独立 Node 服务（04 规格 §19.1）；登录与会话为单管理员＋会话鉴权（04 §2.2／P13、03 规格契约第 67 行）；控制台页面数量口径（03：12 页／04：P01～P13 共 13 个页面编号／总监口径：16 页）不一致，以总监裁定为准，本 PRD 不写死页数；身份源与部署边界见 12.2.2 待裁定。

### 7.13 F13 统一配置入口 `dbdlp.toml`（P0）
三份 YAML 废止，统一 `dbdlp.toml`，优先级严格 **命令行＞配置文件＞默认值**。控制台须展示每个参数生效值与来源层级。字段表见 8.4。验收：同参数三处取值不同启动时生效为命令行值且显来源「命令行」；仅删命令行参数回退为配置文件值；配置文件语法错任务拒启并给具体位置原因。

### 7.14 F14 日志与审计留痕（P0）
五级日志（TRACE／DEBUG／INFO／WARN／ERROR，默认 INFO，FATAL/PANIC 内部保留）；日志行格式、时间戳、编码、双通道、`logs/` 目录与文件命名、轮转策略按 8.3 锁定；日志脱敏禁打印完整手机号／身份证／银行卡／邮箱／凭据明文；审计覆盖数据源变更、连接测试、任务启停、复核结论、报告导出、配置变更、权限拒绝。验收：含敏感值的扫描检索全部日志与视图完整明文命中 0；跨日运行按日切分且超 32 天文件清理；被拒明细导出审计新增含操作者／时间／对象／事件的记录。

### 7.15 F15 凭据加密与密钥管理（P0）
数据源口令等凭据以 ENC(base64) 密文存储；密钥独立管理，不随配置明文落盘、不进版本库；接口与日志不回显明文；密文载荷算法标签布局与解密路由由架构文档按总纲落定。验收：已保存数据源查存储记录与接口响应口令为 ENC(base64) 密文且无明文字段；密钥缺失或权限不足启扫描任务以明确错误拒启且不打印密钥内容。

| MAC | `**:**:**:**:3A:4B` | 保留末两组 |
| 护照／邮编／固话／自定义 | 保留前 2 后 2，`*` 替换其余 | 自定义可指定掩码策略，默认不得输出完整明文 |

任何出口（报告／界面／日志／错误信息／导出／接口响应）均不得出现完整明文敏感值；原始值仅内存瞬时使用，处理完即释放。

### 8.3 存储与目录
- 后端存储库采用 **SQLite 预写日志（WAL）模式**，提升并发读下任务写入与控制台查询稳定性；可选 PostgreSQL 作企业后端（架构文档落定）。
- 运行数据统一落 `data/`：库文件、导入模板与临时文件分目录；目录权限受控。
- 报告写入**项目根 `reports/`**（独立于 `data/`），记录路径与生成时间。
- 日志按总纲落 `项目根目录/logs/`：文件与终端双通道；文件命名 `项目名-YYYYMMDD.log`（如 `dbdlp-20231225.log`）；按日轮转、保留 32 天、自动清理。
- **日志行格式（总纲锁定，全文统一）**：时间戳 `YYYY-MM-DD HH:MM:SS.SSS`（本地时间、不含时区）；行格式 `YYYY-MM-DD HH:MM:SS.SSS  日志级别  trace_id  线程ID或进程ID  模块:行号 - 日志内容`；UTF-8 中文；禁记密码／完整身份证／手机号等。
- 日志级别 TRACE／DEBUG／INFO／WARN／ERROR 五级，默认 INFO，可配置或命令行覆盖（见 8.4）。
- 配置主文件 `dbdlp.toml`；密钥材料不落 `data/` 明文文件，位置由架构文档锁定。

### 8.5 运行留痕与可观测（本地，不外发）
内网离线工具不接外部分析；事件仅写本地审计日志与任务表，不采隐私、不上报 IP、不存原始输入。命名 `{对象}_{动作}`，附 `user_id`、`timestamp`、`device`、`version`。
| 事件类别 | 必埋事件 | 说明 |
|---|---|---|
| 配置 | `data_source_created`、`updated`、`deleted`、`connection_test_completed` | 资产变更与连接测试，含结果不回显凭据 |
| 激活 | `first_scan_completed` | 首任务跑通验部署 |
| 执行 | `scan_started`、`completed`、`failed`、`first_finding_persisted` | 漏斗、失败归因、首条台账落库 |
| 复核 | `review_submitted` | 区分确认敏感／误报／待确认 |
| 导出 | `report_exported` | 三格式分别记，含授权结果 |
| 异常 | `error_occurred` | 前端错误、连接错误、查询超时、规则加载失败、权限拒绝 |

### 8.6 边界条件与状态处理
| 场景 | 要求 |
|---|---|
| 空状态 | 各列表给具体引导（如「还没有数据源，先新增一个并完成连接测试」「本次无命中，可调阈值或扩纳入模式」），禁「暂无数据」类空洞占位 |
| 错误状态 | 区分凭据错误／网络不可达／权限不足／查询超时／规则语法错／密钥缺失；含可定位原因码与下一步，不打印敏感值与凭据 |
| 加载状态 | 长任务显进度与当前对象；分页与导出期间可取消；禁无反馈冻结 |
| 边界值 | 空表、单列表、超长文本、全 NULL 列、单字符值、JSON 空对象、IPv6 压缩、超大批次均须明确结果不崩溃；采样行数配 0 或负值拒启并提示 |
| 并发 | 多任务连接池与并发不超上限；同数据源重复发起须提示冲突；WAL 下写入与查询不互阻 |
| 离线 | 断网／库不可达／密钥不可用／模型缺失（本期不依赖）降级为明确错误，不静默产不完整报告 |
| 权限拒绝 | 未授权导出／越权复核／删被引用数据源均拒并记录审计，界面给原因而非空白页 |

## 9. EARS 格式验收标准表
格式：`While／When／If／Where ＋ 前提或触发 ＋ 系统 ＋ 必须／应该 ＋ 行为`。
| 编号 | 类型 | 前提／触发 | 系统行为 | 级别 | 判定标准 |
|---|---|---|---|---|---|
| E01 | When | 用户提交资产数据源保存 | **必须**先执行只读连接测试，通过才允许保存 | 必须 | 未测或失败保存不可用，审计含原因 |
| E02 | If | 连接测试返回权限不足或凭据错误 | **应该**给可定位原因且不回显口令 | 应该 | 界面与日志均无明文口令 |
| E03 | While | 任务处于低峰窗口外 | **必须**暂停且不向业务库发查询 | 必须 | 库审计无窗口外查询 |
| E04 | While | 扫描任务运行中 | **必须**按主键范围分批并守批次间隔与并发 | 必须 | 无深偏移 `OFFSET`，并发不超上限 |
| E05 | When | 未指定每列采样行数 | **必须**按每列 20 行抽样并写入任务参数与报告 | 必须 | 任一列 `sample_total ≤ 20` |
| E06 | When | 字段值正则初筛未过校验 | **必须**标「待复核」而非高风险 | 必须 | 等级＝待复核，进误报池 |
| E07 | When | 人工提交复核结论 | **必须**单独留存不覆盖原识别结论 | 必须 | 同字段可查机器与复核结论 |
| E08 | If | 某表查询超时或报错 | **应该**有限重试后跳过、记原因并继续 | 应该 | 状态部分失败，其余正常 |
| E09 | If | 任务批次中断 | **应该**恢复时从最近批次主键续扫 | 应该 | 已完成字段不重复台账 |
| E10 | When | 导出 Excel／HTML／JSON 任一 | **必须**只写掩码样例且含实例／模式／表／字段／样本／命中数／风险等级 | 必须 | 全文完整明文命中 0，七项齐备 |
| E11 | Where | 启用批量导入 | **必须**支持 excel 与 yaml，逐行反馈，导入记录默认「未验证」 | 必须 | 错误行不入库给原因，未验证不进扫描 |
| E12 | Where | 报告与日志出现 IPv4 | **必须**按 `*.*.10.3` 脱敏，保留 `127.0.0.1` 与 `localhost` | 必须 | 抽检符合 |
| E13 | When | 同参数命令行／配置文件／默认值三处不同 | **必须**采用命令行值并标注来源层级 | 必须 | 生效值与来源展示一致 |
| E14 | If | `dbdlp.toml` 语法错或规则加载失败 | **必须**拒启并指出位置与原因 | 必须 | 不产生半成品台账 |
| E15 | While | 写入任何日志或审计 | **必须**按五级（默认 INFO）、8.3 格式串与轮转保留 32 天 | 必须 | 分级／格式／切分／清理可验证 |
| E16 | If | 无明细导出权限却发起导出 | **必须**拒绝并记录审计 | 必须 | 无文件产出，审计含操作者／时间／对象／结果 |
| E17 | When | 删除有历史任务引用的数据源 | **必须**二次确认并保留历史可查 | 必须 | 历史报告仍可开，审计含删除事件 |
| E18 | Where | 控制台任意界面 | **应该**用统一矢量图标库，无 emoji 功能图标、无紫粉渐变 | 应该 | 全站走查通过 |
| E19 | When | 新增数据库方言 | **应该**保持采样／识别／分级／报告链路不变 | 应该 | 架构评审确认改动仅在方言层 |
| E20 | If | 密钥缺失／权限不足／不可解密 | **必须**明确错误拒启且不打印密钥 | 必须 | 错误可定位、无敏感输出 |

- 每条内置规则须有正／负样本单测：真实值、订单号、随机数字串、16 位代码注释、掩码值、普通中文、占位文本。

### 10.3 安全与稳定性验收
- 代码评审＋库审计双重确认采集链路仅只读查询。

- 权限拒绝／删被引用对象／配置语法错／密钥缺失等边界按 8.6 与第 9 章产出明确结果。
