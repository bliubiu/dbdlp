> 执行日期：2026-11-14 ｜ 环境：Windows 本机（CLI/serve）＋ `*.*.10.180` e2e 容器（Oracle 11.2.0.4 EE／达梦 DM8）

## 1. 测试范围与方法

对项目四大功能面做黑盒端到端验证：**CLI 数据源管理**、**HTTP API 与 Web 控制台**、**自定义规则链路**、**安全与脱敏约束**。数据面复用 `testdata/` 测试集（e2e 环境已装载 10 表）与新建 SQLite 目标库（`data/e2e_rules.db`，验证自定义规则）。

## 3. 缺陷与处理

| 编号 | 级别 | 描述 | 状态 |
|---|---|---|---|
| DEF-01 | P2 | **CLI 链路零审计**：`datasource add/test/import`、`scan` 均不写 `audit_log`（`AppendAudit` 仅在 HTTP 层 `security.go` 调用）。docs/06 契约要求 CLI 操作同样留痕（`datasource.create/import` 等 action）。 | ✅ **已修复**（datasource 链路）：`application/datasource` 补 `audit` 助手——add 成功记 `datasource.create/success`、门禁拒绝记 `datasource.test/failed`（含中文原因）、import 记 `datasource.import`（partial 语义+失败明细）；actor=`cli`，审计失败仅记 WARN 不影响主流程。真机验证：成功/失败双路径均留痕。CLI `scan` 的任务级审计随 scan 包后续重构一并处理（HTTP 路径已有 `task.start`） |
| DEF-02 | P3 | **样例规则 bytescan 与正则矛盾**：`configs/rules.yaml` 的 `CONTRACT_NO` 正则实际匹配 18 字符（`HT-`＋4 位年份＋`-`＋10 位数字），而 `bytescan.min_len/max_len=16` 导致 18 字符值被字节扫描预过滤、自定义规则**静默不命中**。 | ✅ **已修复**（min/max_len 16→18，重扫 3/3 命中）。教训：自定义规则上线前须以正负样本实测（本测试集即为此设计） |
| DEF-03 | P2 | **负样本池被误判 high（EV-03/EV-04 违约）**：列级聚合以「任一 hit 过校验」置 `VerifyPassed=true`，NG 池中 3 个碰巧通过校验器的纯数字串（订单号过 Luhn／全 0 卡号）把整列抬为 high，掩盖列内大量校验未过的格式命中。 | ✅ **已修复**（`domain/aggregator`）：`ClassifyRisk` 的 high 分支收紧为「校验过 **且** 列名/注释吻合」（对齐 §14.4 置信度维度）；校验过但缺上下文吻合 → `medium`（交人工确认）；列风险为 `pending_review` 时回写 `ReviewStatus=pending_review`（EV-04 分流）。复扫验证：NG 池 high→medium，全库 high 字段 13→11 且全部列名吻合，**EV-03 达成（NG-01~06 判高风险数=0）**。单测新增 `TestAggregatePendingReview`、`TestClassifyRisk` 吻合度双分支 |
| DEF-04 | P3 | **命中率超 100%**：同一采样值命中多条规则时 `HitRatio = len(hits)/sampleTotal` 可达 280%（如 18 位数字串同命中身份证/银行卡/信用代码），违反 docs/04 §4.3 命中率口径。 | ✅ **已修复**（`domain/aggregator`）：`HitRatio` 按采样行数封顶 100%，`命中/样本` 列保留多类型命中明细数语义。复扫验证超 100% 字段为 0 |
| OBS-01 | P4 | 任务列表字段 `tableCount` 抽样为 null（字段名映射待核，任务 id/status 正常），未影响链路。**本轮已定位根因**：前后端 `summary` 字段命名双轨——后端下发 `tableCount`、前端读 `totalTables`，导致前端取不到值；已在 `internal/interfaces/http/views.go` 补同源字段并修复（`views.go:78` `tableCount`、`views.go:84` `totalTables`、`views.go:147` `TotalTables: s.TableCount` 同源赋值），并由 `internal/interfaces/http/task_retry_test.go:111` 断言「控制台汇总字段与后端计数不一致即 fail」守护。 | **已定位／待关闭**（代码已修复，待真实端到端复测确认 `tableCount` 非 null 后由总监就地关闭；本轮不自行改成「已关闭」、不执行复测） |
| OBS-02 | 建议 | 只读守卫 `guardReadOnly` 无独立单测（当前靠架构防护：`ReadOnlyConn` 仅暴露 `Ping/Query/Close`）。建议补 IT-04 直测：构造含 `UPDATE`/分号多语句/注释绕过的查询断言拒绝并记 WARN。 | 待排期 |

## 4. 结论

- 四大功能面 15 项测试 **14 项通过**；唯一功能级缺口为 DEF-01（CLI 审计），安全侧（门禁、鉴权、锁定、脱敏三处、审计 HTTP 层）全部符合契约。
- 自定义规则链路完整可用，但**必须以真实正负样本验证 bytescan 参数**（DEF-02 即为此类隐患的实锤）。
- 复测入口：数据集见 `testdata/`（含期望结果对照表）；本报告测试数据（SQLite 规则库 `data/e2e_rules.db`、导入文件）保留在本地，供回归复用。
