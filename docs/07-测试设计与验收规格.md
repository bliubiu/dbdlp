### 0.5 纪律声明

1. **不得为凑覆盖率写无效断言**：覆盖率是结果不是目标。禁止 `assert.True(true)`、`expect(x).toBeTruthy()`、对 getter 只断言「不为空」、happy-path 堆行。核心逻辑须有注入畏惧缺陷后变红的杀手测试（见 1.8）。
2. **不得凭记忆写第三方库接口**：集成测试签名**只引用 02 文档第 3 章核实结论表**；标「待验证」的能力不写签名、不编断言、不进 CI 必过门（见 4.1）。
3. **测试作者与实现作者解耦**：本文用例由测试角色依据 01 文档验收标准与 02 文档契约反推，不读实现内部假设；研发按本文实现，不得自行改写期望值（见 1.4、1.7）。
4. **本轮不执行测试**：本文为规格文档，所有命令／正则／脚本均为「研发照写」示意，不代表本轮已运行。

## 1. 测试策略与 TDD 分层

### 1.1 测试金字塔与四层映射

```
        /\
       /E2E\          少量：核心用户旅程（控制台闭环 + CLI 成功流/错误流）
      /------\
     /Integr.\        中等：真实方言适配、14 张表、32 条端点、报告导出、批量导入
    /----------\
   / Unit Tests \     大量：校验器、字节扫描器、掩码、分级、置信度、配置、ENC
  /--------------\
```

| 层 | 量级 | 频率 | 真实外部资源 |
|---|---|---|---|
| 单元（UT／RS／NG／BD） | 最多，纯内存零 IO 零网络 | 每次提交 | 否，全用替身 |
| 集成（IT／TB／EP） | 中等，容器化只读库与临时 SQLite | 每次合并／夜间 | 是，须隔离可重建 |
| E2E（AC-A11、SM、22 章） | 少量，单实例单机闭环 | 夜间／放行前 | 是，专用测试数据 |

**四层 DDD 与整洁架构映射**：`domain` 只跑单元测试（纯函数零替身）；`application` 用端口替身跑单元与编排；`infrastructure` 跑集成（真实驱动／SQLite／文件）；`interfaces` 跑 HTTP 契约与少量 E2E。依赖只向内，替身定义在 `domain/port` 由外层注入，禁止领域层 import 测试框架或具体驱动。

### 1.2 四层测试重点与禁止事项

| 层 | 测试重点 | 必须覆盖的高风险行为 | 禁止 |
|---|---|---|---|
| `domain` | 校验器（身份证加权模11、Luhn、统一社会信用代码、邮箱、手机号号段、IPv4/6/MAC）、掩码、置信度 `ConfidenceCalculator`、风险分级 `RiskClassifier`、命中率聚合、ENC 编解码纯函数、配置优先级纯函数 | 边界 off-by-one、校验位 `'X'`、出生日期非法、`sample_total=0` 时 `hit_ratio` 恒 0、IPv4 保留 `127.0.0.1`/`localhost`、映射可配置且历史不改写 | import `database/sql`、`net/http`、驱动、前端框架；读写文件或发日志 |
| `application` | 任务状态机（待执行／运行中／暂停／成功／部分失败／失败）、断点续扫、失败对象单独重试、单表失败不阻断、低峰暂停恢复、批次限流、报告编排、复核不覆盖原始结论、规则版本快照 | 并发冲突（3001）、中断后从 `last_key` 续扫不重复、有限重试上限、映射变更只影响新任务 | 直接写 SQL；绕过端口直连 `infrastructure`；不可观测断言 |
| `infrastructure` | Oracle／达梦只读连接与元数据字典、主键范围分页、流式 `Rows`、SQL 白名单、SQLite WAL 与 14 表、ENC 密钥 0600、日志双通道按日轮转、excelize 六 Sheet、YAML／Excel 解析 | 写操作被拒且记 WARN、分号多语句／注释绕过被拒、深偏移 `OFFSET` 不存在、密钥缺失即终止不回退、格式串与 32 天清理、报告三处无完整明文 | mock 替代真实 SQLite 验 WAL／外键；未核实签名写进适配器（U-01） |
| `interfaces` | 32 条 `/api/v1/` 契约、统一响应 `{code,data,message}` 与分页、错误码表、Bearer 会话、密码占位 `"******"`、控制台 12 页面、九态组件、权限矩阵 | 未认证 1002、越权 1003、明细导出被拒仍记审计、`details` 不含凭据、前端不承载明文 | handler 内重写领域判定；前端直连被监控库 |

### 1.3 测试替身与依赖倒置

| 端口（`domain/port`） | 单测替身 | 集成真实实现 | 替身须制造场景 |
|---|---|---|---|
| `Driver`/`ReadOnlyConn` | 内存只读库：`ListSchemas`/`ListColumns`/`TableStats`/`SampleRows` 预置；`Query` 可注入超时/断连/报错 | Oracle(`oracle`)、达梦(`dm`) 真实只读 | 连接中断、批次超时、单表报错、无主键表、CLOB 超长、BLOB、全 NULL |
| `Engine` | 预置 `DetectValue` 返回固定 `Hit`（仅掩码无 `RawValue`） | 自研四层引擎 | 规则禁用、版本变化、识别降级 |
| `Cipher`/`KeyStore` | 固定 32 字节密钥；注入「不存在/权限不足/长度非32/解码失败」 | 真实 AES-256-GCM 与 SM4-GCM、`crypto/rand` | 四类失败必终止，不返默认密钥 |
| `Logger` | 内存缓冲，可断言级别/格式串/脱敏 | 文件＋终端双通道 | 跨日轮转、32 天清理、任何级别不打印样本原值 |
| `Clock` | 可控时钟 | 系统本地时间 | 低峰边界、按日切分、连接测试结果有效期、会话过期 |
| `Reporter` | 内存 writer 捕获三格式字节 | excelize／模板渲染真实文件 | 大结果集流式不 OOM |
| `RuleRepository` | 内存规则集 | `configs/rules.yaml` 加载与 `rule_snapshot` 落库 | 版本空、`rule_id` 重复、正则不可编译、校验器未注册(2002) |

纪律：替身放 `internal/*/testing` 或 `tests/doubles`，**不得**在 `domain` 内定义；构造函数注入，禁全局单例或 monkey patch；替身「成功」返回须符合契约的一般输入（见 3.7 留出集）。

### 1.4 先写测试与独立测试作者

1. 测试角色在 Phase 2 依据 01 文档第 9/10 章与 02 文档第 13 章**先行反推用例**，不读实现；研发 Phase 3 按本文实现。
2. 写实现与写／审测试上下文分离：研发不得修改本文期望值；疑有误须经总监走变更流程回写，不得就地改测试换绿。
3. 黑盒优先：按「输入 → 可观测输出」断言，不绑定私有函数名／字段名／调用顺序。
4. 独立复核：不写该实现的视角复核「断言真能区分对错」，重点查同义测试与空断言。

### 1.7 测试完整性反作弊门（P0 级）

对比开发前后测试 surface，发现任一类即**阻断（P0）**：

| # | 作弊类型 | 检测 | 判定 |
|---|---|---|---|
| 1 | 测试文件／用例被删 | `git diff --name-status HEAD~1 -- 'tests/' '**/*_test.go' '**/*.test.*' \| grep '^D'`；比对总行数骤减 | 出现 `D` 或行数降无说明 → 阻断 |
| 2 | 断言数下降 | 前后 `expect(`/`assert.`/`t.Errorf` 数量按文件 `diff` | 任一文件断言数降 → 阻断 |
| 3 | 新增 skip/xfail/only/focus | `git diff HEAD~1 -- 'tests/' \| grep -iE 'skip|xfail|\.only|focus|t.Skip'` | 新增未关联已登记缺陷与期限 → 阻断 |
| 4 | 断言硬编码实现自身输出 | 人工复核：期望值是否来自 01/02 文档而非读实现回填 | 「先跑实现再贴进断言」→ 阻断 |
| 5 | 框架配置篡改 | `git diff` 查 `jest/vitest.config`、`pytest.ini`、`package.json`、`Makefile`、`.github/workflows` 的 scripts.test/阈值/必过检查 | 阈值下调/关闭必过/lint 豁免 → 默认拒绝 |

**核心三条反作弊规则（P0，不得放宽）**：① 删测试／删断言或断言数下降即阻断；② 新增 skip／xfail／硬编码实现输出即阻断；③ 篡改框架阈值或关闭必过检查即默认拒绝。

结构性防线（来自 `test-integrity-anti-gaming.md`）：一道作者改不动的确定性校验（GATE-08 跨文档比对、GATE-07 源码扫描、留出集由 CI 独立 runner）；留出集（held-out，研发不可见，专杀特判可见用例）；完整性差异（实现 diff 与测试／门禁 diff 分两段评审）；独立复核（不写该实现的视角输出 `pass`/`fail`＋证据）。

### 1.8 回归率、解决率、变异加固与回归集

| 指标 | 定义 | 达标 |
|---|---|---|
| 解决率 | 目标达成验收条目占比 | 100% |
| **回归率** | 改动引入的、由绿转红的旧行为占比 | **必须为 0；非零即不算完成** |
| 返工次数 | 打回-重做轮数 | ≤3，超限升级总监 |

**改动影响分析模板**（每次测试前必填，入质量报告）：改动范围（文件/函数/接口）→ 下游影响面 → 旧行为风险面（高/中/低）→ 回归优先级。总纲锁定值（日志四项、20 行抽样、ENC 载荷、IPv4 掩码）属**全局共享配置**，任何改动按「高风险旧行为」处理，必须重跑 REG-DOC 全套。

**变异定向加固**（注入最怕的算错方式，要求杀手测试变红）：

| 畏惧缺陷 | 注入 | 必须变红的用例 |
|---|---|---|
| 身份证权重颠倒或模数错 | 改权重数组 | UT-01-03、UT-01-04 |
| Luhn 边界 `<` 非 `<=`、漏翻倍 | 改循环边界 | UT-02-03 |
| IPv4 掩码把 `127.0.0.1` 也打码/只打一段 | 改保留逻辑 | UT-11-05、UT-11-06、ST-04 |
| 每列采样写成 100 或分档 | 改默认 100 | AC-E05、AC-A04、AC-F06 |
| 日志级别回退 ERROR／目录回退 `data/` | 改默认值 | **REG-DOC-01、REG-DOC-02、REG-DOC-05** |
| 密钥失败回退默认全零密钥 | catch 吞错 | UT-15-06、ST-06、AC-E20 |
| 权限判断取反 | 改鉴权分支 | ST-08、AC-E16、AC-A14 |
| 分页 off-by-one 致重复台账 | 改 `last_key` 比较符 | IT-03、AC-E09、AC-A09 |

**回归集沉淀**：每个 P0 缺陷修复后新增 `tests/regression/<缺陷名>_test.go`（前端 `web/tests/regression/`），文件头写 `Regression`/`Discovered`/`Fixed by`，进 GATE-08。**只增不轻删**；删除须总监书面裁定。

### 8.4 打回流程与停滞上限

1. 验证者（不写该实现的独立视角）只看 diff+本文验收标准+契约，输出 `verdict`(pass/fail)、`blocking`(每条带违反标准+证据)、`advisory`、`evidence`。

3. 打回-重做**上限3轮**；连续3轮无进展升级总监。
